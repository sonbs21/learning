Biến của bạn thật sự nằm ở đâu?

Stack, heap và tham chiếu: mô hình bộ nhớ đứng sau gần như mọi câu hỏi phỏng vấn Java.

Sau bài này bạn sẽ Đoán đúng output của mọi câu đố kiểu “Java truyền tham chiếu hay truyền giá trị?” bằng cách vẽ ra stack và heap trong đầu.

Các câu như == và equals, HashMap, String immutable, memory leak trong phong-van.md đều quy về một câu hỏi: khi chạy code, dữ liệu nằm ở đâu và biến chứa cái gì? Bài này trả lời đúng câu hỏi đó.

1. Hai vùng nhớ: stack và heap

Đặc tả JVM (JVMS) chia bộ nhớ lúc chạy thành nhiều vùng. Hai vùng quan trọng nhất là:

“Each Java Virtual Machine thread has a private Java Virtual Machine stack, created at the same time as the thread. A Java Virtual Machine stack stores frames.” — JVMS §2.5.2
“The heap is the run-time data area from which memory for all class instances and arrays is allocated.” — JVMS §2.5.3
  • Stack: mỗi thread có một stack riêng. Mỗi lần gọi method, JVM đẩy lên một frame mới, chứa các biến local và tham số của lần gọi đó. Method chạy xong thì frame bị huỷ (JVMS §2.6).
  • Heap: dùng chung cho mọi thread. Mọi object và mảng tạo bằng new đều nằm ở đây. Không ai tự giải phóng chúng; garbage collector sẽ thu hồi khi không còn ai trỏ tới.
Vì frame bị huỷ ngay khi method kết thúc, biến local “chết” theo method. Object trên heap thì sống tiếp, miễn là còn ít nhất một tham chiếu trỏ tới nó.

2. Biến chứa giá trị, không bao giờ chứa object

Java chỉ có hai loại kiểu (JLS §4):

  • Primitive (int, double, boolean…): biến chứa chính con số đó.
  • Reference (mọi class, interface, mảng): biến chứa một giá trị tham chiếu, tức “địa chỉ” của object trên heap, hoặc null.
“The reference values (often just references) are pointers to these objects, and a special null reference, which refers to no object.” — JLS §4.3.1 
int age = 20;
Person p = new Person("An");
Person q = p;          // copy GIÁ TRỊ tham chiếu, không copy object
Đơn giản hoá: "An" thực ra cũng là một object String riêng trên heap, và field name chỉ giữ tham chiếu tới nó. Bài 2 sẽ nói kỹ.

Vì p và q cùng trỏ một object, chạy q.name = "Giang" rồi đọc p.name sẽ thấy "Giang". Ở đây không có hai object nào cả, chỉ có hai “mũi tên” cùng chỉ vào một chỗ.

Bẫy hay gặp: “primitive luôn nằm trên stack” là sai. Một field int age bên trong object Person nằm trong object đó, tức là trên heap. Thứ quyết định vị trí là biến được khai báo ở đâu (biến local hay field), chứ không phải kiểu của nó.

3. Gọi method: luôn luôn là copy giá trị

Đây là quy tắc chốt cả bài, và nó nằm ngay trong đặc tả ngôn ngữ:

“When the method or constructor is invoked, the values of the actual argument expressions initialize newly created parameter variables […] before execution of the body.” — JLS §8.4.1

Nói cách khác: gọi m(a) tạo một frame mới, trong đó có một biến tham số mới tinh, rồi copy giá trị của a vào đó. Nếu a là primitive thì copy con số; nếu a là reference thì copy mũi tên. Vì thế Java luôn là pass-by-value. Với object, “value” ở đây chính là giá trị tham chiếu.

Từ một quy tắc đó suy ra được hai hệ quả:

  1. Sửa object qua tham chiếu thì bên ngoài thấy. p.name = "Bình" đi theo mũi tên tới object chung và sửa ngay trên object đó.
  2. Gán lại tham số thì bên ngoài không thấy. p = new Person("Bình") chỉ đổi mũi tên trong frame của method. Biến bên ngoài vẫn trỏ object cũ.
static void replace(Person p) { p = new Person("Bình"); }

Person a = new Person("An");
replace(a);
System.out.println(a.name);   // An
Ngôn ngữ có pass-by-reference thật, như ref trong C# hay & trong C++, cho phép method gán lại chính biến của người gọi. Java không có cơ chế này. Đó cũng là lý do bạn không thể viết hàm swap(a, b) đổi chỗ hai biến trong Java.

Nhắc thêm cho chính xác: đây là mô hình theo đặc tả. Khi chạy thật, JIT của HotSpot có thể tối ưu (ví dụ escape analysis có thể khiến một object không bao giờ thực sự được cấp phát trên heap), nhưng hành vi bạn quan sát được luôn giống hệt mô hình này. Nếu tò mò, xem JVM Anatomy Quarks, nhưng chưa cần ngay bây giờ.

Tự kiểm tra trước khi làm quiz: che màn hình lại và trả lời

(1) Gọi method thì cái gì được tạo ra trên stack? (2) Thứ gì được copy vào tham số? (3) Vì sao p.name = … thì bên ngoài thấy, còn p = … thì không?

Đáp án: (1) Một frame mới, chứa các biến tham số mới. (2) Giá trị của đối số: con số nếu là primitive, giá trị tham chiếu nếu là object. (3) Lệnh thứ nhất đi theo mũi tên và sửa object chung trên heap; lệnh thứ hai chỉ đổi mũi tên nằm trong frame riêng của method.

4. Luyện tập: đoán output

Với mỗi câu, hãy vẽ stack và heap ra giấy trước khi bấm. Lớp dùng chung:

class Person { String name; Person(String n) { name = n; } }

Q1. In ra gì?

static void inc(int x) { x = x + 1; }
int a = 10; inc(a); System.out.println(a);
x là một biến mới trong frame của inc, nhận bản copy của số 10. Tăng x không ảnh hưởng gì tới a.

Q2. In ra gì?

static void rename(Person p) { p.name = "Bình"; }
Person a = new Person("An"); rename(a); System.out.println(a.name);
p và a giữ cùng một giá trị tham chiếu. p.name = … đi theo mũi tên và sửa object chung, nên a cũng thấy thay đổi.

Q3. In ra gì?

static void replace(Person p) { p = new Person("Bình"); }
Person a = new Person("An"); replace(a); System.out.println(a.name);
Chính là Hình 2. Lệnh gán chỉ đổi mũi tên của p trong frame của replace, còn a vẫn trỏ object "An".

Q4. In ra gì?

static void swap(Person x, Person y) { Person t = x; x = y; y = t; }
Person a = new Person("An"), b = new Person("Bình");
swap(a, b); System.out.println(a.name + " " + b.name);
swap chỉ tráo hai bản copy x và y trong frame của nó. Biến a và b bên ngoài không đổi. Đây là câu phỏng vấn kinh điển để chứng minh Java không có pass-by-reference.

Q5. In ra gì?

static void tricky(Person p) {
    p.name = "Chi";
    p = new Person("Dũng");
    p.name = "Em";
}
Person a = new Person("An"); tricky(a); System.out.println(a.name);
Dòng 1 sửa object chung, nên a.name thành "Chi". Dòng 2 bẻ mũi tên p sang một object mới, và từ đây p không còn liên quan tới a. Dòng 3 sửa object mới đó, không phải object của a.

Q6. Khi gọi method, thứ gì được copy vào biến tham số?

JLS §8.4.1: giá trị của đối số khởi tạo một biến tham số mới. Object không bao giờ bị copy, chỉ giá trị tham chiếu tới nó được copy.

Q7. Biến local int count khai báo trong main() nằm ở đâu?

Biến local và tham số nằm trong mảng local variables của frame (JVMS §2.6.1).

Q8. Field int age của một object Person nằm ở đâu?

Field là một phần của object, và mọi object đều nằm trên heap. Primitive không mặc nhiên nằm trên stack: vị trí phụ thuộc vào chỗ biến được khai báo.
