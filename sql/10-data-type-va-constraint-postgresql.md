# Tuần 10: Data type và constraint của PostgreSQL

Mục tiêu: chọn kiểu dữ liệu đúng theo ý nghĩa nghiệp vụ và dùng constraint để database chặn dữ liệu sai ngay tại boundary.

Ví dụ tổng hợp:

~~~sql
CREATE TABLE products (
    id bigint GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    sku text NOT NULL UNIQUE,
    price numeric(12, 2) NOT NULL CHECK (price >= 0),
    is_active boolean NOT NULL DEFAULT true,
    created_at timestamptz NOT NULL DEFAULT now()
);
~~~

Trong ví dụ này, bigint dùng cho ID, numeric dùng cho tiền, boolean dùng cho cờ, timestamptz dùng cho thời điểm; NOT NULL, UNIQUE, CHECK và DEFAULT bảo vệ các quy tắc khác nhau.

---

## 1. Nguyên tắc chọn data type

Hãy hỏi:

1. Dữ liệu là số, tiền, thời điểm, cờ hay văn bản?
2. Có miền giá trị hợp lệ không?
3. Có cần timezone không?
4. Có cần query bên trong dữ liệu không?
5. Dữ liệu có ổn định để dùng ENUM không?
6. Có cần NULL hay phải có giá trị mặc định?

| Nhu cầu | Nên dùng |
|---|---|
| ID tăng dần | bigint identity |
| Tiền | numeric |
| Chuỗi | text |
| Cờ đúng/sai | boolean |
| Ngày lịch | date |
| Thời điểm sự kiện | timestamptz |
| ID phân tán hoặc khó đoán | uuid |
| Metadata linh hoạt | jsonb |
| Danh sách đơn giản | array |
| Quan hệ N:N | bảng trung gian |

Không nên dùng text cho mọi column hoặc dùng jsonb để né thiết kế schema.

---

## 2. bigint, integer và identity

PostgreSQL có smallint, integer và bigint. Với ID bảng nghiệp vụ lâu dài, bigint thường an toàn:

~~~sql
CREATE TABLE authors (
    id bigint GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    name text NOT NULL
);
~~~

Các column liên quan phải thống nhất kiểu:

~~~text
authors.id       bigint
books.author_id  bigint
~~~

Identity tự sinh ID:

~~~sql
INSERT INTO authors (name)
VALUES ('George Orwell')
RETURNING id, name;
~~~

GENERATED ALWAYS nghiêm ngặt hơn; ứng dụng không tự chèn ID nếu không dùng cú pháp override. GENERATED BY DEFAULT cho phép cung cấp ID khi cần.

Identity không bảo đảm ID liên tục. Rollback, sequence cache và delete có thể tạo gap. Không dùng ID để làm số hóa đơn liên tục nếu nghiệp vụ yêu cầu không được thiếu số.

## 3. numeric cho tiền

Không dùng real hoặc double precision để lưu tiền vì floating point có thể tạo sai số. Dùng numeric:

~~~sql
price numeric(12, 2) NOT NULL CHECK (price >= 0)
~~~

numeric(12, 2) có tối đa 12 chữ số, trong đó 2 chữ số sau dấu thập phân.

Số lượng:

~~~sql
quantity integer NOT NULL CHECK (quantity > 0)
~~~

Nếu nghiệp vụ cho phép bán theo phần nhỏ như kilogram, dùng numeric và constraint phù hợp.

Phần trăm:

~~~sql
discount_percent numeric(5, 2) NOT NULL DEFAULT 0
    CHECK (discount_percent BETWEEN 0 AND 100)
~~~

PostgreSQL có type money nhưng numeric thường dễ kiểm soát, chuyển đổi và hỗ trợ nhiều currency hơn.

---

## 4. text, varchar và boolean

text là lựa chọn phù hợp cho chuỗi khi không cần giới hạn độ dài ở database:

~~~sql
title text NOT NULL,
description text
~~~

Dùng varchar(n) khi giới hạn là quy tắc nghiệp vụ:

~~~sql
country_code varchar(2) NOT NULL,
postal_code varchar(20)
~~~

Không dùng varchar(255) chỉ vì thói quen từ framework. char(n) tự đệm khoảng trắng và hiếm khi cần trong schema ứng dụng.

Dùng boolean cho cờ:

~~~sql
is_active boolean NOT NULL DEFAULT true,
is_default boolean NOT NULL DEFAULT false
~~~

Tránh dùng text như yes/no hoặc số 0/1. Nếu NULL có nghĩa chưa biết, column có thể nullable; nếu chỉ có hai trạng thái, dùng boolean NOT NULL.

---

## 5. date, timestamp và timestamptz

Dùng date khi chỉ cần ngày:

~~~sql
birth_date date,
due_date date NOT NULL
~~~

timestamp không timezone biểu diễn một ngày-giờ không gắn múi giờ. Nó chỉ phù hợp với các giá trị như giờ trên lịch tại một địa điểm.

Với order, payment, audit event và created_at, dùng timestamptz:

~~~sql
created_at timestamptz NOT NULL DEFAULT now(),
ordered_at timestamptz NOT NULL DEFAULT now()
~~~

timestamptz lưu một thời điểm tuyệt đối; PostgreSQL hiển thị theo timezone của session. Database không lưu tên timezone gốc trong giá trị.

Khuyến nghị:

- lưu event bằng timestamptz;
- thống nhất timezone của session;
- chuyển đổi sang timezone người dùng ở tầng hiển thị;
- không nối chuỗi timezone thủ công.

Khoảng thời gian dùng interval:

~~~sql
SELECT now() + interval '7 days';
~~~

Không dùng interval thay cho timestamp.

## 6. uuid

UUID phù hợp khi ID cần tạo ở nhiều service, khó đoán hoặc không muốn lộ số lượng tuần tự:

~~~sql
CREATE EXTENSION IF NOT EXISTS pgcrypto;

CREATE TABLE api_keys (
    id uuid PRIMARY KEY DEFAULT gen_random_uuid(),
    created_at timestamptz NOT NULL DEFAULT now()
);
~~~

Ưu điểm là tạo phân tán và khó đoán hơn ID tăng dần. Trade-off là index lớn hơn, giá trị khó đọc và UUID ngẫu nhiên có thể kém locality hơn sequence.

UUID không thay thế authorization. ID khó đoán không có nghĩa người dùng được phép truy cập record.

---

## 7. jsonb

jsonb phù hợp với metadata linh hoạt:

~~~sql
CREATE TABLE books (
    id bigint GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    title text NOT NULL,
    metadata jsonb NOT NULL DEFAULT '{}'::jsonb
);
~~~

Query:

~~~sql
SELECT id, title
FROM books
WHERE metadata @> '{"edition": 2}';
~~~

Lấy text field:

~~~sql
SELECT metadata ->> 'publisher' AS publisher
FROM books;
~~~

Có thể tạo GIN index khi query thực tế cần:

~~~sql
CREATE INDEX books_metadata_gin
ON books USING GIN (metadata);
~~~

Không lưu các field nghiệp vụ ổn định như customer_id, status hoặc amount trong jsonb nếu chúng thường được JOIN, filter, aggregate hoặc cần constraint.

Nguyên tắc:

~~~text
Field ổn định và quan trọng → column có type và constraint.
Metadata không ổn định → jsonb.
~~~

## 8. array và ENUM

Array phù hợp với danh sách đơn giản thuộc một row:

~~~sql
CREATE TABLE users (
    id bigint GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    roles text[] NOT NULL DEFAULT ARRAY[]::text[]
);
~~~

Query:

~~~sql
SELECT id
FROM users
WHERE 'reviewer' = ANY(roles);
~~~

Không dùng array cho quan hệ N:N cần foreign key, thuộc tính relationship hoặc cập nhật từng phần tử. Khi đó dùng bảng trung gian.

ENUM phù hợp với tập giá trị nhỏ và ổn định:

~~~sql
CREATE TYPE order_status AS ENUM (
    'pending', 'paid', 'cancelled', 'fulfilled'
);
~~~

ENUM có validation tốt nhưng migration thay đổi giá trị phức tạp hơn. Text + CHECK linh hoạt hơn:

~~~sql
status text NOT NULL CHECK (
    status IN ('pending', 'paid', 'cancelled', 'fulfilled')
)
~~~

Nếu cần label, bản dịch, sort order và active/inactive, dùng lookup table:

~~~sql
CREATE TABLE order_statuses (
    code text PRIMARY KEY,
    display_name text NOT NULL,
    sort_order integer NOT NULL UNIQUE,
    is_active boolean NOT NULL DEFAULT true
);
~~~

## 9. NOT NULL và DEFAULT

NOT NULL thể hiện field bắt buộc:

~~~sql
email text NOT NULL,
created_at timestamptz NOT NULL DEFAULT now()
~~~

DEFAULT chỉ chạy khi INSERT bỏ qua column. Nó không thay NULL được truyền rõ ràng:

~~~sql
INSERT INTO audit_events (event_type, metadata)
VALUES ('book.created', NULL);
~~~

Nếu metadata là NOT NULL, row trên bị chặn. Đừng dùng DEFAULT để che việc application không gửi dữ liệu bắt buộc.

NULL không phải chuỗi rỗng, số 0 hoặc false. Chọn cách biểu diễn dựa trên ý nghĩa nghiệp vụ.

## 10. CHECK constraint

CHECK chặn row khi biểu thức là FALSE:

~~~sql
CREATE TABLE campaigns (
    id bigint GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    starts_at timestamptz NOT NULL,
    ends_at timestamptz NOT NULL,
    CHECK (ends_at > starts_at)
);
~~~

CHECK nhiều column:

~~~sql
CREATE TABLE products (
    id bigint GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    price numeric(12, 2) NOT NULL CHECK (price >= 0),
    stock_quantity integer NOT NULL CHECK (stock_quantity >= 0)
);
~~~

Cẩn thận: CHECK có thể cho qua UNKNOWN khi expression chứa NULL. Field cần bắt buộc phải có cả NOT NULL:

~~~sql
quantity integer NOT NULL CHECK (quantity > 0)
~~~

CHECK không thay thế foreign key. Nếu giá trị phải tồn tại ở bảng khác, dùng foreign key.

---

## 11. UNIQUE và composite UNIQUE

UNIQUE chống trùng một column:

~~~sql
CREATE TABLE customers (
    id bigint GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    email text NOT NULL UNIQUE,
    full_name text NOT NULL
);
~~~

Composite UNIQUE chống trùng tổ hợp:

~~~sql
CREATE TABLE order_items (
    id bigint GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    order_id bigint NOT NULL REFERENCES orders(id),
    book_id bigint NOT NULL REFERENCES books(id),
    quantity integer NOT NULL CHECK (quantity > 0),
    CONSTRAINT order_items_order_book_unique
        UNIQUE (order_id, book_id)
);
~~~

Composite unique không làm từng column riêng lẻ trở thành unique.

PostgreSQL mặc định cho phép nhiều NULL trong unique constraint. Nếu column bắt buộc có giá trị, kết hợp NOT NULL. Với uniqueness có điều kiện, dùng partial unique index:

~~~sql
CREATE UNIQUE INDEX one_active_email
ON customer_emails (lower(email))
WHERE deleted_at IS NULL;
~~~

## 12. Foreign key và ON DELETE

Foreign key bảo đảm row con tham chiếu tới row cha tồn tại:

~~~sql
CREATE TABLE books (
    id bigint GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    author_id bigint REFERENCES authors(id),
    title text NOT NULL
);
~~~

Các hành vi chính:

| Hành vi | Ý nghĩa |
|---|---|
| RESTRICT hoặc NO ACTION | Chặn xóa khi còn row con |
| CASCADE | Xóa row con theo row cha |
| SET NULL | Giữ row con nhưng bỏ liên kết |
| SET DEFAULT | Chuyển về giá trị mặc định hợp lệ |

Order item phụ thuộc hoàn toàn vào order:

~~~sql
order_id bigint NOT NULL
    REFERENCES orders(id)
    ON DELETE CASCADE
~~~

Book đã xuất hiện trong order history thường nên bị RESTRICT hoặc soft delete, không cascade.

Nếu dùng SET NULL, column phải nullable:

~~~sql
author_id bigint REFERENCES authors(id)
    ON DELETE SET NULL
~~~

CASCADE nhiều tầng cần kiểm tra kỹ vì một delete có thể xóa rất nhiều dữ liệu.

## 13. Generated column

Generated column được database tính từ các column cùng row:

~~~sql
CREATE TABLE order_items (
    order_id bigint NOT NULL REFERENCES orders(id),
    book_id bigint NOT NULL REFERENCES books(id),
    quantity integer NOT NULL CHECK (quantity > 0),
    unit_price numeric(12, 2) NOT NULL CHECK (unit_price >= 0),
    line_total numeric(14, 2)
        GENERATED ALWAYS AS (quantity * unit_price) STORED,
    PRIMARY KEY (order_id, book_id)
);
~~~

Generated column phù hợp với công thức thuần túy. Nó khác snapshot nghiệp vụ: unit_price là giá lịch sử được chốt, còn line_total được tính từ unit_price và quantity.

## 14. Schema bookstore tích hợp

~~~sql
CREATE EXTENSION IF NOT EXISTS pgcrypto;

CREATE TABLE authors (
    id bigint GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    name text NOT NULL
);

CREATE TABLE books (
    id bigint GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    author_id bigint REFERENCES authors(id)
        ON DELETE SET NULL,
    isbn text UNIQUE,
    title text NOT NULL,
    price numeric(12, 2) NOT NULL CHECK (price >= 0),
    metadata jsonb NOT NULL DEFAULT '{}'::jsonb,
    is_active boolean NOT NULL DEFAULT true,
    created_at timestamptz NOT NULL DEFAULT now()
);

CREATE TABLE customers (
    id uuid PRIMARY KEY DEFAULT gen_random_uuid(),
    email text NOT NULL UNIQUE,
    full_name text NOT NULL,
    created_at timestamptz NOT NULL DEFAULT now()
);

CREATE TABLE orders (
    id bigint GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    customer_id uuid NOT NULL REFERENCES customers(id),
    status text NOT NULL DEFAULT 'pending' CHECK (
        status IN ('pending', 'paid', 'cancelled', 'fulfilled')
    ),
    ordered_at timestamptz NOT NULL DEFAULT now()
);

CREATE TABLE order_items (
    order_id bigint NOT NULL REFERENCES orders(id)
        ON DELETE CASCADE,
    book_id bigint NOT NULL REFERENCES books(id),
    quantity integer NOT NULL CHECK (quantity > 0),
    unit_price numeric(12, 2) NOT NULL CHECK (unit_price >= 0),
    line_total numeric(14, 2)
        GENERATED ALWAYS AS (quantity * unit_price) STORED,
    PRIMARY KEY (order_id, book_id)
);

CREATE INDEX orders_customer_id_idx
ON orders (customer_id);

CREATE INDEX order_items_book_id_idx
ON order_items (book_id);
~~~

Các lựa chọn chính:

- customer dùng UUID;
- book và order dùng bigint identity;
- tiền dùng numeric;
- metadata dùng jsonb;
- status dùng text + CHECK;
- order_items có composite primary key;
- line_total là generated column;
- item cascade theo order;
- book không bị xóa tự động khỏi lịch sử bán.

## 15. Kiểm tra dữ liệu trước khi thêm constraint

Khi bảng đã có dữ liệu, không thêm constraint mù quáng.

Giá âm:

~~~sql
SELECT id, price
FROM books
WHERE price < 0;
~~~

Email trùng không phân biệt hoa thường:

~~~sql
SELECT lower(email), COUNT(*)
FROM customers
GROUP BY lower(email)
HAVING COUNT(*) > 1;
~~~

Foreign key mồ côi:

~~~sql
SELECT b.author_id
FROM books AS b
LEFT JOIN authors AS a ON a.id = b.author_id
WHERE b.author_id IS NOT NULL
  AND a.id IS NULL;
~~~

Quantity không hợp lệ:

~~~sql
SELECT order_id, book_id, quantity
FROM order_items
WHERE quantity <= 0;
~~~

Quy trình migration:

1. Tìm dữ liệu vi phạm.
2. Sửa hoặc tách dữ liệu.
3. Thêm constraint.
4. Kiểm tra application và rollback plan.
5. Đo thời gian lock trên database lớn.

## 16. Lỗi thường gặp

### Dùng text cho tiền

Dữ liệu text không hỗ trợ tính toán đáng tin cậy. Dùng numeric.

### Dùng double precision cho tiền

Floating point có sai số. Dùng numeric với precision phù hợp.

### Dùng timestamp không timezone cho event

Order, payment và audit event là thời điểm tuyệt đối. Dùng timestamptz.

### Nghĩ DEFAULT thay NULL

DEFAULT chỉ chạy khi column bị bỏ qua. NULL truyền rõ ràng vẫn là NULL.

### Chỉ dùng CHECK mà quên NOT NULL

CHECK có thể cho qua UNKNOWN khi expression chứa NULL. Field bắt buộc cần cả NOT NULL và CHECK.

### Dùng ENUM cho trạng thái thay đổi thường xuyên

Nếu status có metadata, bản dịch hoặc thay đổi thường xuyên, dùng lookup table hoặc text + CHECK.

### Dùng jsonb cho field cần JOIN và constraint

Field ổn định nên là column có type rõ ràng.

### Dùng array cho quan hệ N:N

Nếu phần tử cần foreign key hoặc thuộc tính riêng, dùng bảng trung gian.

### CASCADE quá rộng

Một delete có thể lan qua nhiều bảng. Test trong transaction trước khi bật cascade.

### Chỉ validate ở application

Nhiều service, job hoặc admin script có thể ghi database. Constraint ở database là lớp bảo vệ cuối.

## 17. Bài tập thực hành

### Bài 1 — Chọn data type

Chọn type cho:

~~~text
ID của orders có thể đạt hàng tỷ row
Giá sách có hai chữ số thập phân
Ngày sinh chỉ cần ngày
Thời điểm payment
Cờ sách đang bán
Metadata publisher linh hoạt
Mã định danh public khó đoán
~~~

### Bài 2 — Thiết kế products

Tạo products gồm ID identity, SKU duy nhất, tên bắt buộc, giá không âm, tồn kho không âm, active mặc định true và created_at mặc định now.

### Bài 3 — Composite unique

Tạo inventory với warehouse_id, book_id và quantity. Một book chỉ có một row trong mỗi warehouse.

### Bài 4 — Check nhiều column

Tạo campaigns với starts_at và ends_at; thời điểm kết thúc phải lớn hơn thời điểm bắt đầu.

### Bài 5 — JSONB

Tạo books có metadata jsonb mặc định rỗng. Viết query tìm book có metadata chứa edition bằng 2.

### Bài 6 — ON DELETE

Chọn hành vi phù hợp cho:

~~~text
Order — OrderItem
Author — Book draft
Book — lịch sử OrderItem
Customer — Order lịch sử
~~~

### Bài 7 — ENUM hay lookup

Một hệ thống có status order thường xuyên thêm trạng thái, cần tên hiển thị, bản dịch và thứ tự. Chọn ENUM, CHECK hay lookup table và giải thích.

### Đáp án tham khảo

~~~sql
CREATE TABLE products (
    id bigint GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    sku text NOT NULL UNIQUE,
    name text NOT NULL,
    price numeric(12, 2) NOT NULL CHECK (price >= 0),
    stock_quantity integer NOT NULL CHECK (stock_quantity >= 0),
    is_active boolean NOT NULL DEFAULT true,
    created_at timestamptz NOT NULL DEFAULT now()
);

CREATE TABLE inventory (
    warehouse_id bigint NOT NULL REFERENCES warehouses(id),
    book_id bigint NOT NULL REFERENCES books(id),
    quantity integer NOT NULL CHECK (quantity >= 0),
    PRIMARY KEY (warehouse_id, book_id)
);

CREATE TABLE campaigns (
    id bigint GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    starts_at timestamptz NOT NULL,
    ends_at timestamptz NOT NULL,
    CHECK (ends_at > starts_at)
);

SELECT id, title
FROM books
WHERE metadata @> '{"edition": 2}';
~~~

## 18. Tiêu chí hoàn thành Tuần 10

Bạn hoàn thành bài học khi có thể:

- Chọn bigint hoặc integer dựa trên quy mô dữ liệu.
- Dùng identity và hiểu ID có thể có gap.
- Dùng numeric cho tiền và tránh floating point.
- Phân biệt text, varchar và char.
- Chọn boolean, date, timestamp và timestamptz đúng ngữ nghĩa.
- Biết khi nào dùng UUID.
- Phân biệt field ổn định với metadata phù hợp cho jsonb.
- Biết giới hạn của array và ENUM.
- Dùng NOT NULL, DEFAULT và CHECK đúng vai trò.
- Dùng UNIQUE và composite UNIQUE.
- Thiết kế foreign key và chọn ON DELETE.
- Hiểu CHECK có thể cho qua NULL nếu thiếu NOT NULL.
- Dùng generated column khi giá trị được tính từ cùng row.
- Kiểm tra dữ liệu hiện có trước khi thêm constraint.
- Giải thích vì sao constraint ở database vẫn cần dù application đã validate.

## Tóm tắt cần nhớ

~~~text
ID lớn và lâu dài: bigint identity.
Tiền: numeric, không dùng floating point.
Thời điểm sự kiện: timestamptz.
Cờ đúng/sai: boolean NOT NULL nếu chỉ có hai trạng thái.
Metadata linh hoạt: jsonb; field nghiệp vụ ổn định nên là column riêng.
Array không thay thế bảng trung gian cho N:N.
ENUM hợp với tập nhỏ và ổn định; lookup table hợp với dữ liệu có metadata.
DEFAULT không thay thế NOT NULL.
CHECK không thay thế foreign key và có thể cho qua NULL.
UNIQUE bảo vệ uniqueness; composite UNIQUE bảo vệ tổ hợp.
ON DELETE phải phản ánh vòng đời và dữ liệu lịch sử.
Constraint là lớp bảo vệ toàn vẹn dữ liệu ở boundary.
~~~
