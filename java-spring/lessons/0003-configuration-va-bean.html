@Configuration & @Bean

Bài 3 · Tạo bean cho class mà bạn không thể (hoặc không nên) gắn @Component

~35 phútCần: Bài 2Lab: ./lab

Cho đến giờ, mọi bean đều là class do bạn viết, và bạn chỉ việc gắn @Component lên đó. Nhưng app thật luôn cần object từ thư viện: Clock, ObjectMapper, RestClient, connection pool… Bạn không mở được mã nguồn của chúng để thêm annotation. Vậy làm sao biến chúng thành bean?

1 · Ý tưởng: viết một method tạo object, rồi giao cho Spring

@Configuration                       // "class này chứa các công thức tạo bean"
public class AppConfig {

    @Bean                            // "object mà method này trả về là một bean"
    public Clock clock() {
        return Clock.systemDefaultZone();
    }
}
  1. Spring quét thấy AppConfig vì @Configuration cũng là một dạng @Component.
  2. Spring gọi method clock() một lần và đưa object trả về vào container.
  3. Tên bean mặc định là tên method, ở đây là clock. [docs]
  4. Từ đó, bất kỳ constructor nào cần Clock đều được tiêm bean này, giống hệt bean tạo bằng @Component.

@Service, @Repository, @Controller là gì? Về kỹ thuật, cả ba vẫn là @Component mang tên rõ nghĩa hơn, dùng để báo cho người đọc biết class đó thuộc tầng nào (business logic, truy cập dữ liệu, web). [docs] Từ bài này, ta sẽ dùng @Service cho OrderService.

2 · Thực hành

Lab 3 · ~20 phút

Yêu cầu mới: mỗi đơn hàng phải ghi kèm thời điểm đặt.

  1. Sửa OrderService: đổi @Component thành @Service (import org.springframework.stereotype.Service) và nhận thêm một Clock: 
    package dev.lab;

import java.time.Clock;
import java.time.LocalDateTime;
import org.springframework.stereotype.Service;

@Service
public class OrderService {

    private final EmailSender emailSender;
    private final Clock clock;

    public OrderService(EmailSender emailSender, Clock clock) {
        this.emailSender = emailSender;
        this.clock = clock;
    }

    public void placeOrder(String customer) {
        System.out.println("Đã tạo đơn hàng cho " + customer + " lúc " + LocalDateTime.now(clock));
        emailSender.send(customer, "Cảm ơn bạn đã đặt hàng!");
    }
}
    Chạy luôn, trước khi tạo AppConfig. Đoán trước: lỗi gì sẽ xảy ra, và ở tham số thứ mấy?
  2. Tạo AppConfig.java: 
    package dev.lab;

import java.time.Clock;
import org.springframework.context.annotation.Bean;
import org.springframework.context.annotation.Configuration;

@Configuration
public class AppConfig {

    @Bean
    public Clock clock() {
        return Clock.systemDefaultZone();
    }
}
    Chạy lại. Lần này đơn hàng có in ra giờ hiện tại không?
  3. Đồng hồ giả. Đổi nội dung method clock() thành: 
    return Clock.fixed(Instant.parse("2026-01-01T08:00:00Z"), ZoneOffset.UTC);
    (import java.time.Instant và java.time.ZoneOffset). Chạy lại vài lần. Để ý là OrderService không phải sửa dòng nào.
  4. Xem tên bean. Thêm vào cuối main: 
    System.out.println("Bean tên clock: " + context.getBean("clock"));
Kết quả mong đợi 
# Bước 1: chưa có bean Clock
Parameter 1 of constructor in dev.lab.OrderService required a bean of type
'java.time.Clock' that could not be found.

# Bước 2: đồng hồ hệ thống
Đã tạo đơn hàng cho an@example.com lúc 2026-10-30T22:02:44.105904528

# Bước 3 + 4: đồng hồ cố định, xin bean theo tên
Đã tạo đơn hàng cho an@example.com lúc 2026-01-01T08:00
Bean tên clock: FixedClock[2026-01-01T08:00:00Z,Z]

"Parameter 1" có nghĩa là tham số thứ hai, vì Spring đếm từ 0. Tham số 0 (EmailSender) vẫn ổn. Bước 3 cho thấy giá trị thật của DI: đổi một bean là đổi được hành vi của cả app, không phải sửa class nào dùng bean đó. Khi viết test, ta sẽ dùng đúng kỹ thuật này để có thời gian cố định.

Trạng thái để sang bài 4: giữ AppConfig với Clock.fixed(...) và xoá dòng in "Bean tên clock".
