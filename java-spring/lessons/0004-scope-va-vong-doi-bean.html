Scope & vòng đời của bean

Bài 4 · Spring tạo bao nhiêu object, lúc nào tạo, và lúc nào huỷ

~40 phútCần: Bài 3Lab: ./lab

Đây là bài quan trọng nhất trong 6 bài đầu cho công việc thật. Rất nhiều bug trên production đến từ việc không biết rằng mỗi bean mặc định chỉ có một object, và object đó được mọi người dùng chung.

1 · Scope: một object hay nhiều object?

ScopeSố objectVí dụ đời thường
singleton (mặc định)Một object cho cả containerCái máy in chung của văn phòng
prototypeMỗi lần xin bean là một object mớiTờ giấy: ai cần thì lấy một tờ mới

Ngoài ra còn các scope cho web như request và session. Bài này chưa dùng tới chúng. [docs]

Hệ quả quan trọng Bean singleton được mọi nơi dùng chung. Trong web app, mọi request (có thể hàng nghìn request cùng lúc) đều dùng chung cùng một object OrderService. Vì vậy không được lưu dữ liệu riêng của từng người dùng vào field của bean singleton. Bài 6 sẽ quay lại điểm này.

2 · Vòng đời: tạo → sẵn sàng → huỷ

  1. Constructor: Spring tạo object và tiêm dependency qua constructor.
  2. @PostConstruct: được gọi sau khi dependency đã tiêm xong. Đây là chỗ để "khởi động": mở kết nối, nạp cache…
  3. Bean được dùng trong suốt thời gian app chạy.
  4. @PreDestroy: được gọi khi container đóng (lúc app tắt). Đây là chỗ để "dọn dẹp": đóng kết nối, ghi file…

Hai annotation này nằm ở package jakarta.annotation. [docs]

Ngoại lệ với prototype Với bean prototype, Spring tạo object, giao cho bạn, rồi không theo dõi nó nữa. Vì vậy @PreDestroy của bean prototype không bao giờ được gọi, và việc dọn dẹp là trách nhiệm của người dùng bean. [docs]

3 · Thực hành

Lab 4 · ~25 phút

  1. Theo dõi vòng đời. Sửa ConsoleEmailSender: thêm constructor và 2 method vòng đời: 
    package dev.lab;

import jakarta.annotation.PostConstruct;
import jakarta.annotation.PreDestroy;
import org.springframework.context.annotation.Primary;
import org.springframework.stereotype.Component;

@Primary
@Component
public class ConsoleEmailSender implements EmailSender {

    public ConsoleEmailSender() {
        System.out.println("[1] Constructor ConsoleEmailSender");
    }

    @PostConstruct
    public void connect() {
        System.out.println("[2] @PostConstruct: kết nối tới mail server");
    }

    @PreDestroy
    public void disconnect() {
        System.out.println("[3] @PreDestroy: đóng kết nối mail server");
    }

    @Override
    public void send(String to, String message) {
        System.out.println("Gửi email tới " + to + ": " + message);
    }
}
  2. Giỏ hàng. Tạo ShoppingCart.java với scope prototype: 
    package dev.lab;

import java.util.ArrayList;
import java.util.List;
import jakarta.annotation.PreDestroy;
import org.springframework.context.annotation.Scope;
import org.springframework.stereotype.Component;

@Component
@Scope("prototype")
public class ShoppingCart {

    private final List<String> items = new ArrayList<>();

    public void add(String item) {
        items.add(item);
    }

    public List<String> getItems() {
        return items;
    }

    @PreDestroy
    public void cleanup() {
        System.out.println("ShoppingCart @PreDestroy");
    }
}
  3. Thí nghiệm. Thay phần thân main (từ sau dòng SpringApplication.run) bằng: 
    OrderService a = context.getBean(OrderService.class);
OrderService b = context.getBean(OrderService.class);
System.out.println("OrderService a == b ? " + (a == b));

ShoppingCart cartOfAn = context.getBean(ShoppingCart.class);
ShoppingCart cartOfBinh = context.getBean(ShoppingCart.class);
cartOfAn.add("Áo thun");
System.out.println("ShoppingCart cùng một object ? " + (cartOfAn == cartOfBinh));
System.out.println("Giỏ của An: " + cartOfAn.getItems() + ", giỏ của Bình: " + cartOfBinh.getItems());
    Đoán trước 4 điều: thứ tự in [1] [2] [3]; giá trị a == b; giỏ của Bình có gì; và dòng "ShoppingCart @PreDestroy" có được in không. Sau đó mới chạy.
  4. Gây bug có chủ đích. Xoá dòng @Scope("prototype") để ShoppingCart thành singleton. Chạy lại và xem giỏ của Bình.
Kết quả mong đợi 
# Bước 3: ShoppingCart là prototype
[1] Constructor ConsoleEmailSender
[2] @PostConstruct: kết nối tới mail server
OrderService a == b ? true
ShoppingCart cùng một object ? false
Giỏ của An: [Áo thun], giỏ của Bình: []
[3] @PreDestroy: đóng kết nối mail server
                     ← không có "ShoppingCart @PreDestroy"

# Bước 4: ShoppingCart là singleton
ShoppingCart cùng một object ? true
Giỏ của An: [Áo thun], giỏ của Bình: [Áo thun]   ← Bình thấy đồ của An!
ShoppingCart @PreDestroy
  • [1] và [2] được in trước mọi dòng khác. Lý do: bean singleton được tạo ngay lúc khởi động, chứ không phải lúc bạn gọi getBean.
  • [3] được in sau cùng, lúc app tắt và container đóng lại.
  • Ở bước 4, bạn vừa tự tay tạo ra một bug kinh điển: dữ liệu của người này lọt sang người khác, vì cả hai đang dùng chung một object singleton.

Trạng thái để sang bài 5: trả @Scope("prototype") lại cho ShoppingCart. Các dòng in vòng đời giữ hay xoá đều được.
