Cấu hình bên ngoài code

Bài 5 · application.properties, @Value, ghi đè cấu hình, profile và @ConfigurationProperties

~45 phútCần: Bài 4Lab: ./lab

Cùng một app phải chạy ở nhiều nơi: máy của bạn (dev), server test và production. Mỗi nơi có database, mật khẩu và địa chỉ khác nhau. Nếu viết cứng những giá trị đó trong code thì mỗi lần đổi môi trường là phải sửa code rồi build lại. Spring Boot giải quyết bằng cách đưa cấu hình ra khỏi code. [docs]

1 · Bốn công cụ trong bài này

Công cụDùng để
application.propertiesFile chứa các cặp key=value, nằm trong src/main/resources
@Value("${key}")Tiêm một giá trị vào constructor
Profile (application-dev.properties)Bộ giá trị riêng cho từng môi trường
@ConfigurationPropertiesGom một nhóm key có chung tiền tố vào một object

2 · Ai thắng khi một key được khai báo ở nhiều nơi?

Spring Boot đọc cấu hình từ nhiều nguồn, và nguồn đọc sau ghi đè nguồn đọc trước. Dưới đây là bản rút gọn, xếp từ yếu đến mạnh: [docs]

  1. application.properties trong jar
  2. application-{profile}.properties: file của profile luôn ghi đè file chung
  3. Biến môi trường của hệ điều hành (ví dụ SHOP_NAME)
  4. Tham số dòng lệnh --shop.name=... (mạnh nhất trong danh sách này)

Nhờ vậy, khi chạy trên server, ta chỉ cần đặt biến môi trường hoặc tham số dòng lệnh, không phải đụng tới code hay file trong jar.

3 · Thực hành

Lab 5 · ~30 phút

  1. Đặt main về bản gọn: thân hàm chỉ còn 
    ApplicationContext context = SpringApplication.run(LabApplication.class, args);
context.getBean(OrderService.class).placeOrder("an@example.com");
  2. Thêm cấu hình. Mở lab/src/main/resources/application.properties và thêm vào cuối: 
    shop.name=Son Shop
shop.hotline=1900-1234
  3. @Value. Sửa OrderService để nhận tên cửa hàng (import org.springframework.beans.factory.annotation.Value): 
    private final String shopName;

public OrderService(EmailSender emailSender, Clock clock,
                    @Value("${shop.name}") String shopName) {
    this.emailSender = emailSender;
    this.clock = clock;
    this.shopName = shopName;
}

// trong placeOrder:
emailSender.send(customer, "Cảm ơn bạn đã đặt hàng tại " + shopName + "!");
    Chạy và kiểm tra tên cửa hàng trong email.
  4. Ghi đè bằng dòng lệnh. 
    mvn -o -q spring-boot:run -Dspring-boot.run.arguments=--shop.name=TestShop
    Đoán trước: email in ra "Son Shop" hay "TestShop"?
  5. Profile. Tạo file lab/src/main/resources/application-dev.properties: 
    shop.name=Son Shop (DEV)
    Chạy lần lượt hai lệnh và so sánh: 
    mvn -o -q spring-boot:run
mvn -o -q spring-boot:run -Dspring-boot.run.arguments=--spring.profiles.active=dev
  6. Gõ sai key. Đổi thành @Value("${shop.nam}") rồi chạy và đọc lỗi. Sau đó thử @Value("${shop.nam:Cửa hàng mặc định}"). Phần sau dấu : là giá trị mặc định.
  7. @ConfigurationProperties. Tạo ShopProperties.java: 
    package dev.lab;

import org.springframework.boot.context.properties.ConfigurationProperties;

@ConfigurationProperties(prefix = "shop")
public record ShopProperties(String name, String hotline) {
}
    Sửa OrderService để nhận ShopProperties shop thay cho @Value, và gửi email "Cảm ơn bạn đã đặt hàng tại " + shop.name() + "! Hotline: " + shop.hotline(). Chạy thử: bạn sẽ gặp lỗi gì? Sau đó thêm @ConfigurationPropertiesScan (import org.springframework.boot.context.properties.ConfigurationPropertiesScan) ngay dưới @SpringBootApplication rồi chạy lại.

# Bước 7: chưa có @ConfigurationPropertiesScan
Parameter 2 of constructor in dev.lab.OrderService required a bean of type
'dev.lab.ShopProperties' that could not be found.
# Bước 7: đã có @ConfigurationPropertiesScan
... tại Son Shop! Hotline: 1900-1234

Bước 6 cho thấy Spring dừng app ngay lúc khởi động khi thiếu cấu hình, thay vì chạy tiếp với giá trị null rồi lỗi giữa chừng. Bước 7 là lỗi quen thuộc từ bài 1: @ConfigurationProperties chỉ mô tả cách đọc cấu hình, nó không tự biến class thành bean. Phải có @ConfigurationPropertiesScan thì Spring mới tìm và đăng ký nó. [docs]

Trạng thái để sang bài 6: giữ ShopProperties và @ConfigurationPropertiesScan.

Trong công việc thật Không bao giờ commit mật khẩu thật vào application.properties. Hãy dùng biến môi trường hoặc secret manager trên server, và để file trong repo chỉ chứa giá trị cho dev.
