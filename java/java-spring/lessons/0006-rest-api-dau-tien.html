REST API đầu tiên

Bài 6 · @RestController, GET/POST, @PathVariable, @RequestBody và JSON

~50 phútCần: Bài 5Lab: ./lab + curl

Đây là việc chính của một backend engineer: nhận HTTP request từ app mobile hoặc web, xử lý, rồi trả về JSON. Bạn sẽ thấy mọi thứ đã học ở bài 1–5 đều có mặt ở đây: controller là một bean, service được tiêm qua constructor, và mọi request dùng chung bean singleton.

1 · Một request đi qua những đâu?

  1. Client gửi GET http://localhost:8080/products/1.
  2. Tomcat, web server được Spring Boot nhúng sẵn trong app, nhận request trên port 8080.
  3. Spring MVC tìm method có đường dẫn khớp: @GetMapping("/{id}") trong class @RequestMapping("/products").
  4. Spring chuyển "1" trong URL thành Long id nhờ @PathVariable.
  5. Method trả về một object Product. Thư viện Jackson, được Spring Boot cấu hình sẵn, chuyển object đó thành JSON để gửi về client.

@RestController = @Controller + "giá trị trả về chính là nội dung response". Nó cũng là một @Component, nên cũng là một bean. [docs]

AnnotationLấy dữ liệu từ đâuVí dụ

@RequestParamQuery string/products?page=2
@RequestBodyBody JSON của request{"name":"Áo thun"}

2 · Thực hành

Lab 6 · ~35 phút

  1. Bật web server. Mở application.properties và xoá hai dòng: 
    # Tạm tắt web server cho các bài đầu (chưa học REST API)
spring.main.web-application-type=none
  2. Product.java: dữ liệu sản phẩm 
    package dev.lab;

public record Product(Long id, String name, long price) {
}
  3. ProductService.java: lưu tạm trong bộ nhớ (chưa có database) 
    package dev.lab;

import java.util.List;
import java.util.Map;
import java.util.Optional;
import java.util.concurrent.ConcurrentHashMap;
import java.util.concurrent.atomic.AtomicLong;
import org.springframework.stereotype.Service;

@Service
public class ProductService {

    // ProductService là singleton: mọi request dùng chung map này, nên phải dùng kiểu an toàn đa luồng
    private final Map<Long, Product> products = new ConcurrentHashMap<>();
    private final AtomicLong nextId = new AtomicLong(1);

    public List<Product> findAll() {
        return List.copyOf(products.values());
    }

    public Optional<Product> findById(Long id) {
        return Optional.ofNullable(products.get(id));
    }

    public Product create(String name, long price) {
        Product product = new Product(nextId.getAndIncrement(), name, price);
        products.put(product.id(), product);
        return product;
    }
}
  4. ProductController.java 
    package dev.lab;

import java.util.List;
import org.springframework.http.HttpStatus;
import org.springframework.web.bind.annotation.GetMapping;
import org.springframework.web.bind.annotation.PathVariable;
import org.springframework.web.bind.annotation.PostMapping;
import org.springframework.web.bind.annotation.RequestBody;
import org.springframework.web.bind.annotation.RequestMapping;
import org.springframework.web.bind.annotation.ResponseStatus;
import org.springframework.web.bind.annotation.RestController;
import org.springframework.web.server.ResponseStatusException;

@RestController
@RequestMapping("/products")
public class ProductController {

    private final ProductService productService;

    public ProductController(ProductService productService) {
        this.productService = productService;
    }

    @GetMapping
    public List<Product> findAll() {
        return productService.findAll();
    }

    @GetMapping("/{id}")
    public Product findById(@PathVariable Long id) {
        return productService.findById(id)
                .orElseThrow(() -> new ResponseStatusException(HttpStatus.NOT_FOUND));
    }

    @PostMapping
    @ResponseStatus(HttpStatus.CREATED)
    public Product create(@RequestBody Product request) {
        return productService.create(request.name(), request.price());
    }
}
  5. Chạy server ở một terminal: mvn -o -q spring-boot:run. Lần này app không tự thoát, vì nó đang chờ request. Tìm dòng log Tomcat started on port 8080. Khi cần tắt thì bấm Ctrl+C.
  6. Gọi API từ một terminal khác. Với mỗi lệnh, hãy đoán status code trước rồi mới chạy: 
    curl -i http://localhost:8080/products
curl -i -X POST http://localhost:8080/products \
     -H 'Content-Type: application/json' -d '{"name":"Áo thun","price":150000}'
curl -i -X POST http://localhost:8080/products \
     -H 'Content-Type: application/json' -d '{"name":"Quần jean","price":450000}'
curl -i http://localhost:8080/products
curl -i http://localhost:8080/products/1
curl -i http://localhost:8080/products/99
curl -i http://localhost:8080/products/abc
  7. Tắt server rồi bật lại, sau đó gọi lại GET /products. Hai sản phẩm vừa tạo còn không? Vì sao?
Kết quả mong đợi 
GET  /products        → 200  []
POST /products        → 201  {"id":1,"name":"Áo thun","price":150000}
POST /products        → 201  {"id":2,"name":"Quần jean","price":450000}
GET  /products        → 200  [{"id":1,...},{"id":2,...}]
GET  /products/1      → 200  {"id":1,"name":"Áo thun","price":150000}
GET  /products/99     → 404  {"timestamp":"...","status":404,"error":"Not Found","path":"/products/99"}
GET  /products/abc    → 400  {"timestamp":"...","status":400,"error":"Bad Request","path":"/products/abc"}
  • 404 là do code của bạn ném ResponseStatusException(NOT_FOUND). Body JSON đó là trang lỗi mặc định của Spring Boot.
  • 400 xảy ra trước khi method của bạn được gọi: Spring không chuyển được "abc" thành Long.
  • Sau khi khởi động lại, danh sách sản phẩm trống, vì dữ liệu chỉ nằm trong RAM của bean ProductService. Đó là lý do ta cần database, chủ đề của các bài tới.
  • Bạn không viết dòng nào để chuyển object thành JSON. Spring Boot đã tự cấu hình Jackson khi thấy thư viện đó trên classpath. Đây chính là auto-configuration, và ta sẽ mổ xẻ nó trong một bài sau.
