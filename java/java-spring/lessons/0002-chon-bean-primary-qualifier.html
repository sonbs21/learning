Có nhiều ứng viên, Spring chọn bean nào?

Bài 2 · @Primary, @Qualifier và cách nhận tất cả bean cùng kiểu

~35 phútCần: Bài 1Lab: ./lab

Ở Thí nghiệm B của bài 1, bạn đã gặp lỗi required a single bean, but 2 were found. Chuyện này rất hay xảy ra trong dự án thật: một interface thường có nhiều cách cài đặt (email/SMS, MySQL/Postgres, thanh toán Momo/VNPay…). Bài này dạy bạn ba cách để nói cho Spring biết bạn muốn bean nào.

1 · Vì sao Spring không tự chọn?

Constructor của OrderService chỉ nói "tôi cần một EmailSender". Trong container lại có hai bean thoả điều kiện đó. Nếu Spring tự đoán, app của bạn có thể gửi SMS cho khách mà không ai hay biết. Vì vậy Spring chọn cách an toàn hơn: dừng lại và báo lỗi.

2 · Ba cách giải quyết

CáchĐặt ở đâuÝ nghĩa
@PrimaryTrên class được chọn"Nếu không ai nói gì thêm thì dùng tôi." Đây là lựa chọn mặc định.
@Qualifier("tênBean")Trên chỗ nhận (tham số constructor)"Chỗ này tôi cần đúng bean tên này." Đây là chỉ định đích danh.
List<EmailSender>Kiểu của tham số"Đưa tôi tất cả bean thuộc kiểu này."
Quy tắc cần nhớ @Primary là mặc định chung, còn @Qualifier là yêu cầu cụ thể tại một chỗ. Khi có cả hai thì yêu cầu cụ thể thắng. Docs của Spring cũng mô tả @Qualifier là cách kiểm soát việc chọn bean chặt chẽ hơn @Primary. [docs]

Nhắc lại từ bài 1: tên bean mặc định là tên class với chữ cái đầu viết thường, nên SmsSender có tên là smsSender. @Qualifier dùng chính tên này.

3 · Thực hành

Lab 2 · ~20 phút

Bắt đầu từ trạng thái cuối bài 1: có EmailSender, ConsoleEmailSender và OrderService.

  1. Tạo lại lỗi. Tạo SmsSender.java: 
    package dev.lab;

import org.springframework.stereotype.Component;

@Component
public class SmsSender implements EmailSender {

    @Override
    public void send(String to, String message) {
        System.out.println("Gửi SMS tới " + to + ": " + message);
    }
}
    Chạy mvn -o -q spring-boot:run. Bạn sẽ gặp lại lỗi "2 were found".
  2. Cách 1: @Primary. Thêm @Primary (import org.springframework.context.annotation.Primary) lên ConsoleEmailSender: 
    @Primary
@Component
public class ConsoleEmailSender implements EmailSender { ... }
    Chạy lại. Đoán trước: app sẽ gửi email hay SMS?
  3. Cách 2: @Qualifier. Giữ nguyên @Primary, nhưng sửa constructor của OrderService (import org.springframework.beans.factory.annotation.Qualifier): 
    public OrderService(@Qualifier("smsSender") EmailSender emailSender) {
    Chạy lại. Bây giờ bean nào thắng?
  4. Gõ sai tên. Đổi thành @Qualifier("smsSendr"), thiếu chữ "e". Chạy lại và đọc kỹ lỗi.
  5. Cách 3: nhận tất cả. Bỏ @Qualifier khỏi OrderService. Tạo NotificationService.java: 
    package dev.lab;

import java.util.List;
import org.springframework.stereotype.Component;

@Component
public class NotificationService {

    private final List<EmailSender> senders;

    public NotificationService(List<EmailSender> senders) {
        this.senders = senders;
    }

    public void broadcast(String to, String message) {
        System.out.println("Có " + senders.size() + " kênh gửi");
        senders.forEach(sender -> sender.send(to, message));
    }
}
    Trong main, ngay sau dòng placeOrder, thêm: 
    context.getBean(NotificationService.class).broadcast("an@example.com", "Khuyến mãi 50%!");
Kết quả mong đợi (mở sau khi đã tự đoán) 
# Bước 2: @Primary
Gửi email tới an@example.com: Cảm ơn bạn đã đặt hàng!

# Bước 3: @Qualifier("smsSender") thắng @Primary
Gửi SMS tới an@example.com: Cảm ơn bạn đã đặt hàng!

# Bước 4: gõ sai tên
Parameter 0 of constructor in dev.lab.OrderService required a bean of type
'dev.lab.EmailSender' that could not be found.
The injection point has the following annotations:
	- @org.springframework.beans.factory.annotation.Qualifier("smsSendr")

# Bước 5: List nhận cả hai bean
Có 2 kênh gửi
Gửi email tới an@example.com: Khuyến mãi 50%!
Gửi SMS tới an@example.com: Khuyến mãi 50%!

Để ý ở bước 4: Spring không lặng lẽ quay về dùng bean @Primary. Bạn đã yêu cầu đích danh một tên thì tên đó phải tồn tại. Thông báo lỗi còn chỉ rõ annotation nào gây ra lỗi.

Trạng thái để sang bài 3: giữ @Primary trên ConsoleEmailSender, không có @Qualifier trong OrderService, giữ SmsSender và NotificationService. Xoá dòng broadcast trong main cho output gọn.
