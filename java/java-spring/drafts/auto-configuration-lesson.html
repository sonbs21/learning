Auto-configuration không phải phép màu

Bài 1 · Bắt Spring Boot tự khai ra vì sao nó tạo (hoặc không tạo) một bean

~40 phútLab: ./labSpring Boot 3.5.16

Câu hỏi số 4 trong ../boot/phong-van.md: "Spring Boot Auto-Configuration hoạt động như thế nào?". Hầu hết ứng viên trả lời "Boot tự cấu hình dựa trên dependency". Câu đó không sai, nhưng nó chưa giải thích được gì. Sau bài này bạn sẽ trả lời được kèm bằng chứng lấy từ chính máy mình. Trong công việc, đây cũng là kỹ năng đầu tiên cần dùng khi gặp lỗi kiểu "sao bean này không có / sao cấu hình của tôi không ăn".

Ý tưởng cốt lõi

Auto-configuration chỉ là các class @Configuration bình thường. Mỗi class được gắn thêm điều kiện @Conditional…, và Spring xét chúng sau các bean do bạn tự khai báo.

Khi bạn chạy SpringApplication.run(...), chuyện xảy ra theo thứ tự sau:

  1. @SpringBootApplication thực chất là ba annotation gộp lại: @Configuration + @EnableAutoConfiguration + @ComponentScan. [docs]
  2. @ComponentScan tìm bean của bạn trong package của class main và các package con.
  3. @EnableAutoConfiguration đọc file META-INF/spring/org.springframework.boot.autoconfigure.AutoConfiguration.imports trong từng jar trên classpath. Mỗi dòng của file là một class auto-config ứng viên. [docs]
  4. Với mỗi ứng viên, Spring kiểm tra các điều kiện, thường gặp nhất là hai cái:
    @ConditionalOnClass: class X có trên classpath không? (tức là bạn có thêm dependency đó chưa)
    @ConditionalOnMissingBean: bạn đã tự khai báo bean kiểu này chưa? [docs]
  5. Điều kiện đạt thì bean được tạo, không đạt thì bỏ qua. Mọi quyết định đều được ghi lại trong Conditions Evaluation Report, và cờ --debug sẽ in report đó ra. [docs]
Vì sao "bean của bạn luôn thắng"? Theo docs, auto-configuration được đảm bảo nạp sau các bean definition do người dùng khai báo. Nhờ vậy, khi @ConditionalOnMissingBean được xét, nó đã thấy hết bean của bạn. Cũng vì lý do này mà docs khuyên chỉ dùng @ConditionalOnBean/@ConditionalOnMissingBean trong class auto-configuration: đặt ở @Configuration của bạn thì thứ tự nạp không được đảm bảo. [docs]

Thí nghiệm: bắt Boot tự khai

Lab 1 · ~20 phút

  1. Đếm số ứng viên. Boot có sẵn bao nhiêu auto-config? 
    unzip -p ~/.m2/repository/org/springframework/boot/spring-boot-autoconfigure/3.5.16/spring-boot-autoconfigure-3.5.16.jar \
  META-INF/spring/org.springframework.boot.autoconfigure.AutoConfiguration.imports | wc -l
    Ghi lại con số. Sau đó thay wc -l bằng grep Jackson và tìm tên class lo việc tạo ObjectMapper.
  2. Chạy app với --debug (project ./lab đã có sẵn, chỉ gồm starter-web): 
    cd lab
mvn -o -q spring-boot:run \
  -Dspring-boot.run.arguments="--debug --spring.main.web-application-type=none" > run.log
grep -n "CONDITIONS EVALUATION REPORT" run.log
  3. Tìm một positive match. Trong run.log, tìm jacksonObjectMapper. Đọc dòng ngay bên dưới nó: điều kiện nào đã đạt, và vì sao?
  4. Tìm một negative match. Tìm DataSourceAutoConfiguration:. Vì sao Boot không tạo DataSource? Nó đang thiếu class nào?
  5. Bắt Boot lùi lại (back off). Tạo file lab/src/main/java/dev/lab/MapperConfig.java và tự khai báo một bean ObjectMapper: 
    package dev.lab;

import com.fasterxml.jackson.databind.ObjectMapper;
import org.springframework.context.annotation.Bean;
import org.springframework.context.annotation.Configuration;

@Configuration
class MapperConfig {

    @Bean
    ObjectMapper myMapper() {
        return new ObjectMapper();
    }
}
    Chạy lại bước 2. Bây giờ jacksonObjectMapper nằm ở mục nào của report? Message của nó nhắc đến tên bean nào?
Đối chiếu kết quả (chỉ mở sau khi đã tự làm) 
# Bước 1: 156 dòng; class cần tìm là JacksonAutoConfiguration

# Bước 3 (Positive matches)
JacksonAutoConfiguration.JacksonObjectMapperConfiguration#jacksonObjectMapper matched:
   - @ConditionalOnMissingBean (types: com.fasterxml.jackson.databind.ObjectMapper; ...)
     did not find any beans (OnBeanCondition)

# Bước 4 (Negative matches)
DataSourceAutoConfiguration:
   Did not match:
   - @ConditionalOnClass did not find required class
     'org.springframework.jdbc.datasource.embedded.EmbeddedDatabaseType'

# Bước 5 (đã chuyển sang Negative matches)
JacksonAutoConfiguration.JacksonObjectMapperConfiguration#jacksonObjectMapper:
   Did not match:
   - @ConditionalOnMissingBean ... found beans of type '...ObjectMapper' myMapper

Đây chính là câu trả lời phỏng vấn, kèm bằng chứng: cùng một class auto-config, cùng một điều kiện, chỉ khác là bạn có khai báo bean hay không.

Giữ lại MapperConfig.java hay xoá tuỳ bạn. Bài sau sẽ dùng lại project này.
