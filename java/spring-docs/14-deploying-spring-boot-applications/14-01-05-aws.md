# 14.1.5. Amazon Web Services (AWS)

> Nguồn: <https://docs.spring.io/spring-boot/docs/3.2.5/reference/htmlsingle/#deployment.cloud.aws>

Amazon Web Services cung cấp nhiều cách để cài đặt các ứng dụng dựa trên Spring Boot, dưới dạng ứng dụng web truyền thống (war) hoặc dưới dạng file jar thực thi với web server nhúng. Các tùy chọn bao gồm:

- AWS Elastic Beanstalk
- AWS Code Deploy
- AWS OPS Works
- AWS Cloud Formation
- AWS Container Registry

Mỗi tùy chọn có các tính năng và mô hình định giá khác nhau. Trong tài liệu này, chúng tôi mô tả cách tiếp cận dùng AWS Elastic Beanstalk.

## AWS Elastic Beanstalk

Như được mô tả trong [hướng dẫn Java Elastic Beanstalk](https://docs.aws.amazon.com/elasticbeanstalk/latest/dg/create_deploy_Java.html) chính thức, có hai tùy chọn chính để triển khai một ứng dụng Java. Bạn có thể dùng "Tomcat Platform" hoặc "Java SE platform".

### Sử dụng Tomcat Platform (Using the Tomcat Platform)

Tùy chọn này áp dụng cho các project Spring Boot tạo ra file war. Không cần cấu hình đặc biệt nào. Bạn chỉ cần làm theo hướng dẫn chính thức.

### Sử dụng Java SE Platform (Using the Java SE Platform)

Tùy chọn này áp dụng cho các project Spring Boot tạo ra file jar và chạy một web container nhúng. Các môi trường Elastic Beanstalk chạy một instance nginx trên cổng 80 để làm proxy cho ứng dụng thực tế chạy trên cổng 5000. Để cấu hình nó, hãy thêm dòng sau vào file `application.properties`:

```
server.port=5000
```

> **MẸO (TIP):** **Tải lên file nhị phân thay vì mã nguồn (Upload binaries instead of sources)**
>
> Theo mặc định, Elastic Beanstalk tải mã nguồn lên và biên dịch chúng trên AWS. Tuy nhiên, tốt nhất nên tải file nhị phân lên thay thế. Để làm vậy, hãy thêm các dòng tương tự như sau vào file `.elasticbeanstalk/config.yml`:

```xml
deploy:
    artifact: target/demo-0.0.1-SNAPSHOT.jar
```

> **MẸO (TIP):** **Giảm chi phí bằng cách đặt loại môi trường (Reduce costs by setting the environment type)**
>
> Theo mặc định, một môi trường Elastic Beanstalk được cân bằng tải (load balanced). Load balancer có chi phí đáng kể. Để tránh chi phí đó, hãy đặt loại môi trường thành "Single instance", như được mô tả trong [tài liệu Amazon](https://docs.aws.amazon.com/elasticbeanstalk/latest/dg/environments-create-wizard.html#environments-create-wizard-capacity). Bạn cũng có thể tạo các môi trường single instance bằng CLI và lệnh sau:

```
eb create -s
```

## Tóm tắt (Summary)

Đây là một trong những cách dễ nhất để lên AWS, nhưng còn nhiều thứ khác cần đề cập, chẳng hạn như cách tích hợp Elastic Beanstalk vào bất kỳ công cụ CI / CD nào, dùng Maven plugin Elastic Beanstalk thay cho CLI, và các vấn đề khác. Có một [bài blog](https://exampledriven.wordpress.com/2017/01/09/spring-boot-aws-elastic-beanstalk-example/) đề cập chi tiết hơn về các chủ đề này.
