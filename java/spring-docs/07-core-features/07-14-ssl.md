# 7.14. SSL

> Nguồn: <https://docs.spring.io/spring-boot/docs/3.2.5/reference/htmlsingle/#features.ssl>

Spring Boot cung cấp khả năng cấu hình tài liệu tin cậy SSL (SSL trust material) có thể được áp dụng cho nhiều loại kết nối khác nhau để hỗ trợ giao tiếp an toàn. Các configuration property có tiền tố `spring.ssl.bundle` có thể được dùng để chỉ định các bộ tài liệu tin cậy có tên và thông tin liên quan.

## 7.14.1. Cấu hình SSL với file Java KeyStore (Configuring SSL With Java KeyStore Files)

> Nguồn: <https://docs.spring.io/spring-boot/docs/3.2.5/reference/htmlsingle/#features.ssl.jks>

Các configuration property có tiền tố `spring.ssl.bundle.jks` có thể được dùng để cấu hình các bundle tài liệu tin cậy được tạo bằng tiện ích `keytool` của Java và được lưu trong các file Java KeyStore ở định dạng JKS hoặc PKCS12. Mỗi bundle có một tên do người dùng cung cấp, có thể dùng để tham chiếu tới bundle đó.

Khi được dùng để bảo mật một web server nhúng, một `keystore` thường được cấu hình với một Java KeyStore chứa certificate và private key như trong ví dụ này:

**Properties**

```properties
spring.ssl.bundle.jks.mybundle.key.alias=application
spring.ssl.bundle.jks.mybundle.keystore.location=classpath:application.p12
spring.ssl.bundle.jks.mybundle.keystore.password=secret
spring.ssl.bundle.jks.mybundle.keystore.type=PKCS12
```

**Yaml**

```yaml
spring:
  ssl:
    bundle:
      jks:
        mybundle:
          key:
            alias: "application"
          keystore:
            location: "classpath:application.p12"
            password: "secret"
            type: "PKCS12"
```

Khi được dùng để bảo mật một kết nối phía client, một `truststore` thường được cấu hình với một Java KeyStore chứa certificate của server như trong ví dụ này:

**Properties**

```properties
spring.ssl.bundle.jks.mybundle.truststore.location=classpath:server.p12
spring.ssl.bundle.jks.mybundle.truststore.password=secret
```

**Yaml**

```yaml
spring:
  ssl:
    bundle:
      jks:
        mybundle:
          truststore:
            location: "classpath:server.p12"
            password: "secret"
```

Xem [JksSslBundleProperties](https://github.com/spring-projects/spring-boot/tree/v3.2.5/spring-boot-project/spring-boot-autoconfigure/src/main/java/org/springframework/boot/autoconfigure/ssl/JksSslBundleProperties.java) để có đầy đủ các property được hỗ trợ.

## 7.14.2. Cấu hình SSL với certificate mã hóa PEM (Configuring SSL With PEM-encoded Certificates)

> Nguồn: <https://docs.spring.io/spring-boot/docs/3.2.5/reference/htmlsingle/#features.ssl.pem>

Các configuration property có tiền tố `spring.ssl.bundle.pem` có thể được dùng để cấu hình các bundle tài liệu tin cậy ở dạng văn bản mã hóa PEM. Mỗi bundle có một tên do người dùng cung cấp, có thể dùng để tham chiếu tới bundle đó.

Khi được dùng để bảo mật một web server nhúng, một `keystore` thường được cấu hình với certificate và private key như trong ví dụ này:

**Properties**

```properties
spring.ssl.bundle.pem.mybundle.keystore.certificate=classpath:application.crt
spring.ssl.bundle.pem.mybundle.keystore.private-key=classpath:application.key
```

**Yaml**

```yaml
spring:
  ssl:
    bundle:
      pem:
        mybundle:
          keystore:
            certificate: "classpath:application.crt"
            private-key: "classpath:application.key"
```

Khi được dùng để bảo mật một kết nối phía client, một `truststore` thường được cấu hình với certificate của server như trong ví dụ này:

**Properties**

```properties
spring.ssl.bundle.pem.mybundle.truststore.certificate=classpath:server.crt
```

**Yaml**

```yaml
spring:
  ssl:
    bundle:
      pem:
        mybundle:
          truststore:
            certificate: "classpath:server.crt"
```

> **MẸO (TIP):** Nội dung PEM có thể được dùng trực tiếp cho cả hai property `certificate` và `private-key`. Nếu giá trị property chứa các dấu `BEGIN` và `END` thì chúng sẽ được coi là nội dung PEM thay vì vị trí của một resource.

## 7.14.3. Áp dụng SSL bundle (Applying SSL Bundles)

> Nguồn: <https://docs.spring.io/spring-boot/docs/3.2.5/reference/htmlsingle/#features.ssl.applying>

Sau khi được cấu hình bằng property, các SSL bundle có thể được tham chiếu theo tên trong các configuration property cho nhiều loại kết nối khác nhau được Spring Boot tự động cấu hình. Xem các phần về [web server nhúng](https://docs.spring.io/spring-boot/docs/3.2.5/reference/htmlsingle/#howto.webserver.configure-ssl), [các công nghệ dữ liệu](https://docs.spring.io/spring-boot/docs/3.2.5/reference/htmlsingle/#data), và [REST client](https://docs.spring.io/spring-boot/docs/3.2.5/reference/htmlsingle/#io.rest-client) để biết thêm thông tin.

## 7.14.4. Sử dụng SSL bundle (Using SSL Bundles)

> Nguồn: <https://docs.spring.io/spring-boot/docs/3.2.5/reference/htmlsingle/#features.ssl.bundles>

Spring Boot tự động cấu hình một bean kiểu `SslBundles` cung cấp quyền truy cập tới từng bundle có tên được cấu hình bằng các property `spring.ssl.bundle`.

Một `SslBundle` có thể được lấy từ bean `SslBundles` được tự động cấu hình và dùng để tạo các object được dùng để cấu hình kết nối SSL trong các thư viện client. `SslBundle` cung cấp một cách tiếp cận phân lớp để lấy các object SSL này:

- `getStores()` cung cấp quyền truy cập tới các instance `java.security.KeyStore` của key store và trust store cũng như mọi mật khẩu key store cần thiết.
- `getManagers()` cung cấp quyền truy cập tới các instance `java.net.ssl.KeyManagerFactory` và `java.net.ssl.TrustManagerFactory` cũng như các mảng `java.net.ssl.KeyManager` và `java.net.ssl.TrustManager` mà chúng tạo ra.
- `createSslContext()` cung cấp một cách tiện lợi để lấy một instance `java.net.ssl.SSLContext` mới.

Ngoài ra, `SslBundle` cung cấp chi tiết về key đang được dùng, giao thức cần dùng và mọi tùy chọn nên được áp dụng cho SSL engine.

Ví dụ sau cho thấy việc lấy một `SslBundle` và dùng nó để tạo một `SSLContext`:

**Java**

```java
import javax.net.ssl.SSLContext;

import org.springframework.boot.ssl.SslBundle;
import org.springframework.boot.ssl.SslBundles;
import org.springframework.stereotype.Component;

@Component
public class MyComponent {

    public MyComponent(SslBundles sslBundles) {
        SslBundle sslBundle = sslBundles.getBundle("mybundle");
        SSLContext sslContext = sslBundle.createSslContext();
        // do something with the created sslContext
    }

}
```

**Kotlin**

```kotlin
import org.springframework.boot.ssl.SslBundles
import org.springframework.stereotype.Component

@Component
class MyComponent(sslBundles: SslBundles) {

    init {
        val sslBundle = sslBundles.getBundle("mybundle")
        val sslContext = sslBundle.createSslContext()
        // do something with the created sslContext
    }

}
```

## 7.14.5. Nạp lại SSL bundle (Reloading SSL bundles)

> Nguồn: <https://docs.spring.io/spring-boot/docs/3.2.5/reference/htmlsingle/#features.ssl.reloading>

Các SSL bundle có thể được nạp lại khi key material thay đổi. Component sử dụng bundle phải tương thích với các SSL bundle có thể nạp lại. Hiện tại các component sau là tương thích:

- Web server Tomcat
- Web server Netty

Để bật việc nạp lại, bạn cần chủ động bật (opt-in) thông qua một configuration property như trong ví dụ này:

**Properties**

```properties
spring.ssl.bundle.pem.mybundle.reload-on-update=true
spring.ssl.bundle.pem.mybundle.keystore.certificate=file:/some/directory/application.crt
spring.ssl.bundle.pem.mybundle.keystore.private-key=file:/some/directory/application.key
```

**Yaml**

```yaml
spring:
  ssl:
    bundle:
      pem:
        mybundle:
          reload-on-update: true
          keystore:
            certificate: "file:/some/directory/application.crt"
            private-key: "file:/some/directory/application.key"
```

Khi đó, một file watcher sẽ theo dõi các file và nếu chúng thay đổi, SSL bundle sẽ được nạp lại. Đến lượt nó, điều này kích hoạt việc nạp lại trong component sử dụng bundle, ví dụ Tomcat sẽ xoay vòng (rotate) các certificate trong các connector có bật SSL.

Bạn có thể cấu hình khoảng thời gian yên lặng (quiet period) (để đảm bảo không còn thay đổi nào nữa) của file watcher bằng property `spring.ssl.bundle.watch.file.quiet-period`.
