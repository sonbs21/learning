Chuyện gì xảy ra khi bạn chạy một chương trình Java?

Bài 1 · Hiểu đường đi từ file code bạn viết đến lúc máy tính chạy nó

~30 phútCần biết: viết được một class Java đơn giảnThư mục thực hành: lab/l0001

Mỗi ngày bạn bấm nút Run trong IDE và chương trình chạy. Nhưng giữa lúc bấm nút và lúc chữ hiện ra trên màn hình đã xảy ra mấy bước. Bài này đi qua từng bước một, chậm rãi, có ví dụ và có lệnh để bạn tự chạy và tự thấy.

Học xong bài này, bạn sẽ:

  • Kể lại được 3 bước để một chương trình Java chạy được.
  • Biết javac, .class, JVM là gì và mỗi thứ làm việc gì.
  • Trả lời được câu phỏng vấn: "Java là ngôn ngữ biên dịch hay thông dịch?"

1 · Bắt đầu bằng một câu chuyện

Bạn là đầu bếp người Việt, viết một công thức nấu ăn bằng tiếng Việt. Bạn muốn công thức này được nấu ở nhà hàng tại Nhật, Mỹ và Pháp. Vấn đề là đầu bếp ở đó không đọc được tiếng Việt.

Có hai cách giải quyết:

  • Cách 1: Viết riêng 3 bản: tiếng Nhật, tiếng Anh, tiếng Pháp. Mỗi lần sửa công thức lại phải sửa cả 3 bản. Rất mệt.
  • Cách 2: Dịch công thức một lần sang một "ngôn ngữ chung". Nhà hàng nào cũng thuê sẵn một phiên dịch viên hiểu ngôn ngữ chung này. Phiên dịch viên đọc bản chung rồi nói lại cho đầu bếp địa phương bằng tiếng của họ.

Java chọn cách 2.

Giờ ta ghép từng vai trong câu chuyện với thứ tương ứng trong Java:

Bạn chỉ viết code một lần. File .class giống nhau ở mọi máy. Cái khác nhau giữa các máy chỉ là JVM. Đây chính là khẩu hiệu nổi tiếng của Java: "Write once, run anywhere" (viết một lần, chạy mọi nơi).

2 · Tự làm từng bước

Mở terminal và đi theo từng bước dưới đây. Mỗi bước đều có phần "Bạn sẽ thấy" để bạn so với kết quả trên máy mình.

Bước 1: Xem file code (công thức tiếng Việt)

cd lab/l0001
cat Hello.java
public class Hello {
    public static void main(String[] args) {
        int a = 2;
        int b = 3;
        System.out.println("Tổng = " + (a + b));
    }
}

Đây là code bình thường, bạn đọc hiểu được. Nhưng CPU không đọc được file này.

Bước 2: Biên dịch bằng javac (dịch sang ngôn ngữ chung)

javac Hello.java
ls
Hello.class  Hello.java  Lazy.java

Có một file mới xuất hiện: Hello.class. Đó là kết quả của việc biên dịch. Thử mở nó ra xem:

cat Hello.class

Một đống ký tự lạ, gần như không đọc được.

Thấy ký tự lạ là đúng. File này không viết cho người đọc, mà viết cho JVM đọc. Nội dung bên trong là bytecode: một danh sách lệnh rất đơn giản kiểu "đẩy số 2 vào", "đẩy số 3 vào", "cộng hai số lại".

Bước 3: Chạy bằng java (phiên dịch viên làm việc)

java Hello
Tổng = 5

Chú ý: bạn gõ java Hello, không có đuôi .java hay .class. Lệnh java khởi động JVM. JVM sẽ tự đi tìm file Hello.class, rồi làm ba việc theo thứ tự:

  1. Nạp (load): tìm file Hello.class và đọc vào bộ nhớ. Giống phiên dịch viên lấy bản công thức ra khỏi tủ.
  2. Kiểm tra (verify): xem bytecode có hợp lệ, có an toàn không. Giống phiên dịch viên đọc lướt xem công thức có bước nào nguy hiểm hay viết sai không.
  3. Chạy (execute): dịch từng lệnh bytecode sang mã máy cho CPU làm. Giống phiên dịch viên đọc từng bước công thức cho đầu bếp nấu.

3 · Phiên dịch viên thông minh: JIT

Ở bước "chạy", JVM có hai cách làm việc:

Phiên dịch viên ban đầu dịch miệng từng câu một. Cách này bắt đầu nhanh, nhưng nếu một câu phải dịch đi dịch lại 10 000 lần thì rất phí công.

Vì vậy phiên dịch viên để ý: câu nào được hỏi rất nhiều lần thì viết sẵn bản dịch ra giấy. Lần sau chỉ cần đưa tờ giấy, khỏi phải dịch lại.

  • Dịch miệng từng câu = thông dịch (interpreter). Khởi động nhanh, nhưng chạy chậm.
  • Viết sẵn bản dịch cho câu hay dùng = JIT (Just-In-Time compiler). Đoạn code nào chạy nhiều lần sẽ được dịch hẳn sang mã máy, và từ đó chạy rất nhanh.

Bạn có thể tự kiểm tra: gõ java -version và nhìn dòng cuối.

OpenJDK 64-Bit Server VM (build 21...., mixed mode, sharing)

mixed mode nghĩa là "chế độ kết hợp": JVM vừa thông dịch, vừa dùng JIT.

Câu phỏng vấn: "Java là ngôn ngữ biên dịch hay thông dịch?"

Trả lời: cả hai. Có thể nói như sau:

"Đầu tiên javac biên dịch code thành bytecode trong file .class. Khi chạy, JVM thông dịch bytecode đó. Đoạn nào chạy nhiều thì JIT biên dịch tiếp sang mã máy để chạy nhanh hơn."

4 · Một lỗi thật bạn sẽ gặp khi đi làm

Bản "ngôn ngữ chung" cũng có phiên bản. Mỗi đời Java mới có thể thêm từ mới vào ngôn ngữ chung. Xem phiên bản của file vừa tạo:

javap -v Hello | grep major
  major version: 65

Số 65 nghĩa là Java 21. Mấy con số hay gặp: 52 = Java 8, 61 = Java 17, 65 = Java 21. (javap là công cụ có sẵn trong JDK để "soi" bên trong file .class.)

Công thức viết bằng ngôn ngữ chung bản mới nhất, nhưng phiên dịch viên chỉ học bản cũ. Anh ta sẽ nói: "Tôi không đọc được bản này."

Trong Java, tình huống đó sinh ra lỗi UnsupportedClassVersionError. Ví dụ: bạn build code bằng Java 21 trên máy mình, rồi đem lên server chỉ cài Java 17. Cách sửa là cài đúng bản Java trên server, hoặc build cho bản Java cũ hơn.

5 · Tóm tắt

  1. Bạn viết Hello.java, file code người đọc được.
  2. javac dịch nó thành Hello.class, file chứa bytecode (ngôn ngữ chung).
  3. java khởi động JVM. JVM nạp → kiểm tra → chạy bytecode, và dùng JIT để tăng tốc đoạn chạy nhiều.

6 · Tự kiểm tra

Đừng nhìn lại bài khi làm. Nghĩ ra đáp án trong đầu trước rồi mới bấm chọn.

7 · Thử thách nhỏ: JVM có nạp hết mọi thứ không?

Mở file Lazy.java. Trong đó có hai class: Lazy và Helper. Class Helper chỉ được dùng khi bạn truyền thêm một chữ bất kỳ lúc chạy (ví dụ java Lazy x).

Câu hỏi: nếu chạy java Lazy (không thêm chữ nào), JVM có nạp Helper không? Hãy đoán trước, rồi chạy thử:

javac Lazy.java
ls *.class
java -Xlog:class+load Lazy   | grep -E ' (Lazy|Helper) '
java -Xlog:class+load Lazy x | grep -E ' (Lazy|Helper) '

(-Xlog:class+load bảo JVM in ra mỗi lần nó nạp một class. grep lọc ra chỉ những dòng có chữ Lazy hoặc Helper.)

Xem đáp án

Lệnh ls cho thấy cả hai file Lazy.class và Helper.class đều có trên ổ cứng (mỗi class là một file riêng).

Nhưng lần chạy không có chữ thì JVM chỉ nạp Lazy. Lần chạy có chữ x thì mới thấy thêm dòng Helper.

Kết luận: JVM lười. Nó chỉ nạp một class khi thật sự cần dùng tới. Giống phiên dịch viên không lấy hết công thức trong tủ ra, mà chỉ lấy đúng món đang được gọi.

Đào sâu: nhìn tận mắt bytecode

Lệnh javap -c Hello in bytecode ra dưới dạng đọc được. Đây là phần của hàm main, kèm giải thích:

iconst_2     // đẩy số 2 vào một "chồng đĩa" tạm
istore_1     // lấy ra, cất vào biến a
iconst_3     // đẩy số 3
istore_2     // cất vào biến b
iload_1      // đẩy a lên chồng
iload_2      // đẩy b lên chồng
iadd         // lấy 2 số trên cùng ra, cộng lại, đẩy kết quả lên

JVM tính toán bằng một "chồng đĩa" (gọi là operand stack): đặt số lên, lấy số xuống. Bạn chưa cần nhớ các lệnh này. Chỉ cần biết bytecode thật ra là một danh sách lệnh rất đơn giản như trên.

Bạn cũng sẽ thấy một hàm Hello() mà bạn không hề viết. Đó là constructor mặc định: javac tự thêm vào cho mọi class không tự khai báo constructor.[JLS §8.8.9]
