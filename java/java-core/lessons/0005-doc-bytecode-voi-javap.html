Đừng tin, hãy javap

Đọc bytecode để tận mắt thấy frame, operand stack, pass-by-value và constant folding.

Sau bài này bạn sẽ Chạy javap -c trên code của chính mình và đọc được khoảng 10 instruction phổ biến nhất. Từ đó tự kiểm chứng mọi khẳng định ở Bài 1–2 mà không cần tin ai.
Ôn lại Bài 1 và 4

(1) Một frame chứa những gì? (2) HashMap mặc định chuyển từ 32 lên 64 ô ở lần put thứ mấy?

Đáp án: (1) Biến local (gồm cả tham số) và phần trung gian của phép tính; bài này sẽ gọi đúng tên phần đó là operand stack. (2) Lần thứ 25, vì threshold = 32 × 0.75 = 24.

1. Frame có hai phần: local variables và operand stack

Bài 1 mới nói frame chứa biến local. Thật ra JVM là một máy stack: mỗi frame có thêm một operand stack làm “bàn nháp” để tính toán.

“The Java Virtual Machine supplies instructions to load constants or values from local variables or fields onto the operand stack. Other Java Virtual Machine instructions take operands from the operand stack, operate on them, and push the result back onto the operand stack.” — JVMS §2.6.2

Biến local được đánh số theo slot: 0, 1, 2… Theo JVMS §2.6.1, với method static, tham số chiếm các slot liên tiếp bắt đầu từ 0. Với method instance thì slot 0 luôn là this.

2. Cách chạy

javac -d /tmp/l5 lessons/code/L0005Bytecode.java
javap -c -p -cp /tmp/l5 L0005Bytecode

-c in bytecode, -p hiện cả method private (javap man page). Mọi output bên dưới là kết quả chạy thật trên JDK 21.

3. Đọc add(int a, int b): một phép tính

static int add(int a, int b) { int sum = a + b; return sum; }

0: iload_0     // đẩy giá trị slot 0 (a) lên operand stack
1: iload_1     // đẩy b                         stack: [a, b]
2: iadd        // lấy 2 số ra, cộng, đẩy kết quả stack: [a+b]
3: istore_2    // lấy ra, cất vào slot 2 (sum)
4: iload_2     // đẩy sum
5: ireturn     // trả về giá trị trên đỉnh stack

Tiền tố của instruction cho biết kiểu dữ liệu: i là int, a là reference, l là long, d là double (JVMS §2.11.1).

4. Bằng chứng cho pass-by-value

// main:  int x = 10;  int y = add(x, 5);
0: bipush 10
2: istore_1          // x ở slot 1 (slot 0 là args)
3: iload_1           // đẩy BẢN COPY giá trị của x lên stack
4: iconst_5
5: invokestatic add  // 2 giá trị trên stack thành slot 0, 1 của frame MỚI
8: istore_2

invokestatic lấy các giá trị trên operand stack của người gọi và đặt chúng vào local variables của frame mới. Không có instruction nào truyền “chính biến x”; chỉ có giá trị của nó được truyền đi. Với object cũng y như vậy:

// rename(an);   rồi bên trong:  p.name = "Bình";
19: aload_3            // đẩy GIÁ TRỊ THAM CHIẾU của an
20: invokestatic rename

// trong rename:
0: aload_0             // đẩy tham chiếu p (bản copy)
1: ldc "Bình"          // đẩy tham chiếu tới String "Bình" trong constant pool
3: putfield name       // đi theo tham chiếu, ghi vào field của OBJECT CHUNG
Đây chính là Hình 2 của Bài 1, nhưng viết bằng ngôn ngữ của JVM.

5. Tạo object là 3 bước

// Person an = new Person("An");
 9: new  Person          // cấp phát object trên heap, đẩy tham chiếu
12: dup                  // nhân đôi tham chiếu (1 cho constructor, 1 để gán)
13: ldc "An"
15: invokespecial Person."<init>"   // gọi constructor
18: astore_3             // cất tham chiếu vào slot 3 (an)

Cấp phát (new) và khởi tạo (invokespecial <init>) là hai bước tách biệt. Chi tiết này sẽ quan trọng khi học concurrency, vì ở đó có khả năng một thread khác nhìn thấy object “nửa vời”.

6. Constant folding và nối chuỗi

// String s = "hi" == "hi" ? "same" : "diff";
23: ldc "same"           // không có phép so sánh nào cả!
25: astore 4

// String t = an.name + y;
27: aload_3
28: getfield name
31: iload_2
32: invokedynamic makeConcatWithConstants   // nối chuỗi lúc runtime

Vì "hi" == "hi" là một biểu thức hằng (JLS §15.29 cho phép dùng == trong biểu thức hằng), compiler tính luôn và chỉ để lại ldc "same". Còn an.name + y không phải hằng, nên được nối lúc runtime qua invokedynamic, cơ chế nối chuỗi có từ Java 9. Đây là bằng chứng bytecode cho các câu ở Bài 2.

10 instruction cần nhớ: iload/aload (local lên stack), istore/astore (stack về local), ldc (hằng từ constant pool), new + dup + invokespecial (tạo object), getfield/putfield, invokestatic/invokevirtual, ireturn/areturn/return.

7. Luyện tập

Q1 (ôn Bài 4). HashMap mặc định, put tới phần tử thứ 25 thì table.length thành?

Bảng 32 ô có threshold 24. Lần put thứ 25 làm size vượt 24, nên bảng gấp đôi lên 64.

Q2. Trong method static int add(int a, int b), tham số a nằm ở local slot nào?

Method static không có this, nên tham số bắt đầu từ slot 0 (JVMS §2.6.1). Nếu là method instance thì a sẽ ở slot 1.

Q3. Instruction nào đẩy một reference từ biến local lên operand stack?

Tiền tố a là reference. ldc nạp hằng từ constant pool, không phải từ biến local.

Q4. Sau new Person + dup, instruction nào gọi constructor?

Constructor là method đặc biệt <init> và được gọi bằng invokespecial.

Q5. "hi" == "hi" ? "same" : "diff" biên dịch thành gì?

Đây là biểu thức hằng nên được tính lúc compile. Bytecode chỉ còn ldc "same".

Q6. Trước invokestatic rename, bytecode đẩy gì lên operand stack?

aload_3 đẩy giá trị tham chiếu đang nằm trong slot 3. Object vẫn ở nguyên trên heap.

8. Tự làm

Tạo file của riêng bạn có method void swap(Person x, Person y) như ở Bài 1, rồi javap -c nó. Bạn sẽ thấy chỉ có aload/astore giữa các slot của frame swap, và không có instruction nào chạm được tới biến của người gọi.

Nguồn chính nên đọc: JVMS Chapter 6: The JVM Instruction Set. Đừng đọc hết; mỗi khi gặp một instruction lạ trong javap, hãy tra đúng mục của nó. Hướng dẫn công cụ: dev.java: javap.
