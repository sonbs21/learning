this và super thật ra là gì?

Bài 6 · this là một tham số ẩn, super là "gọi bản của cha", và cái bẫy gọi method bị override ngay trong constructor

~35 phútCần biết: Bài 1 (javap, slot 0), Bài 5 (thứ tự cha–con)Thư mục thực hành: lab/l0006

Học xong bài này, bạn sẽ:

  • Hiểu this là gì ở cấp độ JVM, và vì sao method static không dùng được this.
  • Dùng đúng 4 dạng: this.field, this(...), super.method(), super(...).
  • Tránh được một bẫy phỏng vấn kinh điển: gọi method bị override trong constructor của class cha.

1 · Ôn bài 1 và bài 5 (trả lời trong đầu trước)

(a) Trong bytecode của một constructor, lệnh aload_0 đẩy cái gì lên stack?

(b) new Child() lần đầu: thứ tự chạy giữa static và constructor của cha và con là gì?

Kiểm tra(a) aload_0 đẩy giá trị trong slot 0, tức là this. (b) static cha → static con → constructor cha → constructor con. Cả hai câu này đều quay lại trong bài hôm nay.

2 · this là một tham số mà bạn không nhìn thấy

Một công ty có quy định chung "nhân viên mặc đồng phục". Quy định đó viết một lần cho tất cả. Nhưng khi áp dụng thì luôn là cho một người cụ thể: "bạn mặc đồng phục".

Method trong Java cũng vậy: code chỉ viết một lần trong class, nhưng mỗi lần gọi a.chao(...) hay b.chao(...) thì nó chạy cho một object cụ thể. Method biết "object hiện tại là ai" nhờ một tham số ẩn mà JVM tự truyền vào. Tham số ẩn đó chính là this.

Kiểm chứng bằng bytecode. File HiddenThis.java có hai method, mỗi method khai báo đúng 1 tham số:

String chao(String loiChao)        { return loiChao + " " + this.ten; }   // method thường
static String chaoStatic(String loiChao) { return loiChao; }               // method static
cd lab/l0006
javac HiddenThis.java
javap -v HiddenThis | grep -E 'chao|args_size'
javap -c HiddenThis
  java.lang.String chao(java.lang.String);
      stack=2, locals=2, args_size=2      ← khai báo 1 tham số mà có 2!
  static java.lang.String chaoStatic(java.lang.String);
      stack=1, locals=1, args_size=1

java.lang.String chao(java.lang.String);
   0: aload_1          // slot 1 = loiChao
   1: aload_0          // slot 0 = this
   2: getfield ten     // this.ten

static java.lang.String chaoStatic(java.lang.String);
   0: aload_0          // slot 0 = loiChao (không có this!)
  • Method thường: args_size=2 dù chỉ khai báo 1 tham số. Tham số thứ hai, nằm ở slot 0, chính là this.
  • Method static: không có this, nên slot 0 là tham số đầu tiên. Đúng như bạn đã thấy ở bài 1 và bài 2.

Đó là lý do static không dùng được this. Method static không gắn với object nào, nên chẳng có "object hiện tại" để truyền vào. File loi/StaticThis.java thử dùng this trong main:

javac loi/StaticThis.java
loi/StaticThis.java:4: error: non-static variable this cannot be referenced from a static context
this = tham chiếu tới object đang chạy method. JVM tự truyền nó vào slot 0 của mọi method không static và mọi constructor.[JLS §15.8.3]

3 · Dạng 1: this.field, khi tên bị "che"

Khi tham số trùng tên với field, tên tham số sẽ che (shadow) field. Mở Shadow.java:

String ten;
void setTenSai(String ten)  { ten = ten; }        // quên this
void setTenDung(String ten) { this.ten = ten; }   // có this

Đoán trước: sau setTenSai("An"), field ten bằng bao nhiêu?

javac Shadow.java && java Shadow
Sau setTenSai : ten = null
Sau setTenDung: ten = An

Trong setTenSai, cả hai chữ ten đều là tham số, nên dòng đó chỉ gán tham số cho chính nó. Field không hề được đụng tới. Không có lỗi biên dịch, không có exception, field chỉ âm thầm vẫn là null. this.ten nghĩa là "field ten của object hiện tại", và nó phá được sự che khuất đó.[Oracle Tutorial: Using the this Keyword]

4 · Dạng 2: this(...), constructor gọi constructor

Khi có nhiều constructor, thay vì chép đi chép lại code gán field, một constructor có thể gọi constructor khác bằng this(...). Mở Chain.java:

SanPham(String ten, int gia, int soLuong) {    // constructor "đầy đủ"
    this.ten = ten; this.gia = gia; this.soLuong = soLuong;
    System.out.println("  constructor 3 tham số chạy");
}
SanPham(String ten, int gia) {
    this(ten, gia, 1);                           // gọi constructor kia, soLuong mặc định 1
    System.out.println("  constructor 2 tham số chạy");
}
javac Chain.java && java Chain
  constructor 3 tham số chạy
  constructor 2 tham số chạy
bút / 5000 / 1

new SanPham("bút", 5000) vào constructor 2 tham số. Constructor đó gọi ngay this(..., 1), nên constructor 3 tham số chạy trước, xong mới quay lại chạy phần còn lại. Logic gán field chỉ nằm ở một chỗ.

5 · Dạng 3 và 4: super, gọi bản của cha

super.method(): mở rộng thay vì viết lại

Khi override, đôi khi bạn không muốn thay thế hoàn toàn method của cha, mà muốn thêm vào. Mở SuperCall.java:

class TaiKhoan {
    String moTa() { return "Tài khoản thường"; }
}
class TaiKhoanVip extends TaiKhoan {
    @Override
    String moTa() { return super.moTa() + " + ưu đãi VIP"; }   // gọi bản của CHA rồi thêm
}
javac SuperCall.java && java SuperCall
Tài khoản thường + ưu đãi VIP

Nếu viết moTa() (hay this.moTa()) thay vì super.moTa(), method sẽ gọi lại chính nó, đệ quy mãi cho tới StackOverflowError (bài 2). super. nghĩa là "bỏ qua bản override của tôi, gọi thẳng bản của class cha".[Oracle Tutorial: Using the Keyword super]

super(...): phải là câu lệnh đầu tiên

Nhớ lại bài 1: javac tự chèn super() vào đầu mọi constructor. Nếu class cha không có constructor không tham số, bạn phải tự gọi super(...) với tham số phù hợp. Và trong Java 21, lời gọi đó phải đứng đầu tiên. File loi/SuperNotFirst.java thử làm ngược lại:

Con() {
    System.out.println("chạy trước super");
    super("Bình");
}
javac loi/SuperNotFirst.java
loi/SuperNotFirst.java:5: error: call to super must be first statement in constructor

Lý do: phần "cha" của object phải được khởi tạo xong trước khi phần "con" chạy. Đây đúng là thứ tự "constructor cha → constructor con" ở bài 5.[JLS §8.8.7.1] (Từ Java 25, quy tắc này được nới ra một chút: được phép chạy một số câu lệnh trước super(...), miễn là không đụng tới this.[JEP 513] Máy bạn đang dùng Java 21, nên vẫn áp dụng quy tắc cũ.)

6 · Bẫy kinh điển: gọi method bị override trong constructor của cha

Đây là câu phỏng vấn khiến rất nhiều người trả lời sai. Mở ConstructorTrap.java:

class Cha {
    Cha() {
        System.out.println("Cha(): gọi gioiThieu() → " + gioiThieu());
    }
    String gioiThieu() { return "tôi là Cha"; }
}
class Con extends Cha {
    private final String ten = layTen();          // "Bình"
    Con() {
        super();
        System.out.println("Con(): gọi gioiThieu() → " + gioiThieu());
    }
    @Override
    String gioiThieu() { return "tôi là Con, tên " + ten; }
}

new Con();

Đoán trước: dòng đầu tiên in ra "tôi là Cha" hay "tôi là Con"? Nếu là Con, tên in ra là gì? (Gợi ý: ten là field final, tức không gán lại được sau khi khởi tạo.)

javac ConstructorTrap.java && java ConstructorTrap
Cha(): gọi gioiThieu() → tôi là Con, tên null
Con(): gọi gioiThieu() → tôi là Con, tên Bình

Hai điều bất ngờ:

  1. Constructor của Cha lại gọi bản của Con. Object đang được tạo là một Con, nên this trong Cha() trỏ tới object Con đó. Lời gọi gioiThieu() được chọn theo kiểu thật của object, không theo class đang chứa đoạn code.
  2. Field final lại là null. Theo thứ tự ở bài 5, constructor cha chạy trước, rồi các field của con mới được gán (ten = layTen() chạy sau super()). Lúc Cha() chạy, ten vẫn đang mang giá trị mặc định null. Ngay cả final cũng không cứu được.
Không gọi method có thể bị override từ trong constructor. Class con có thể override method đó, và nó sẽ chạy khi các field của con chưa được khởi tạo. Kết quả là null, 0, hoặc NullPointerException.
Nếu buộc phải gọi, hãy dùng method private, final hoặc static (những loại không override được).

Effective Java, Item 19, ghi đúng quy tắc này: "Constructors must not invoke overridable methods, directly or indirectly."

Câu phỏng vấn: "this và super khác nhau thế nào? Gọi method bị override trong constructor thì sao?"

"this là tham chiếu tới object hiện tại, được JVM truyền ngầm vào slot 0 của mọi method không static. Nó dùng để phân biệt field với tham số trùng tên (this.x = x) và để gọi constructor khác trong cùng class (this(...)). super dùng để gọi bản method của class cha (super.m()) và constructor của class cha (super(...), phải là câu lệnh đầu tiên). Gọi method có thể bị override từ constructor là nguy hiểm: nếu class con override nó, bản của con sẽ chạy khi field của con chưa được khởi tạo, vì constructor cha chạy trước. Kết quả thường là null hoặc NullPointerException."

8 · Thử thách: sửa ConstructorTrap.java

Nhiệm vụ: sửa ConstructorTrap.java sao cho không còn dòng nào in ra null. Có nhiều cách. Hãy thử ít nhất một cách, rồi giải thích vì sao nó hiệu quả.

Gợi ý:

  • Cách A: đừng gọi gioiThieu() trong constructor của Cha nữa. Ai cần thì gọi sau khi object đã tạo xong.
  • Cách B: trong Cha(), gọi một method private của Cha thay vì gioiThieu(). Method private không bị override.
Xem một lời giải (cách A) 
static class Cha {
    Cha() {
        System.out.println("Cha(): khởi tạo xong phần của Cha");   // không gọi method override được
    }
    String gioiThieu() { return "tôi là Cha"; }
}
...
public static void main(String[] args) {
    Con c = new Con();
    System.out.println(c.gioiThieu());     // gọi SAU khi object đã khởi tạo xong
}
Cha(): khởi tạo xong phần của Cha
tôi là Con, tên Bình

Khi constructor đã chạy xong hết, mọi field đều đã có giá trị đúng. Gửi cách giải của bạn cho agent để được nhận xét.

Đào sâu: this bị lộ ra ngoài khi constructor chưa xong

Có một biến thể nguy hiểm hơn của bẫy ở mục 6: constructor đưa this ra ngoài trước khi chạy xong, ví dụ đăng ký this làm listener, bỏ this vào một list static, hoặc khởi động một thread dùng this. Nơi nhận có thể dùng object khi field của nó chưa được gán.

Điều này còn phá luôn đảm bảo của field final (sẽ học kỹ ở bài 16): JLS §17.5 chỉ đảm bảo các thread khác thấy đúng giá trị field final nếu "do not write a reference to the object being constructed in a place where another thread can see it before the object's constructor is finished".[JLS §17.5] Tóm lại: constructor chỉ nên làm một việc là khởi tạo field, không gọi method có thể bị override, và không đưa this ra ngoài.
