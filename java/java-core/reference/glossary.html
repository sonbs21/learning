Glossary

Thuật ngữ Java core dùng thống nhất trong mọi bài. Thêm dần theo từng bài.

Thuật ngữNghĩaBài
bytecodeTập lệnh cho JVM (máy ảo), không phụ thuộc OS/CPU. Nằm trong file .class.1
class fileFile .class: magic CAFEBABE + version + constant pool + field/method + bytecode. Mỗi class là một file.1
major versionPhiên bản class file. 52 = Java 8, 61 = Java 17, 65 = Java 21. Nếu JVM cũ hơn → UnsupportedClassVersionError.1
javacCompiler: .java → .class. Chạy lúc build.1
JVMChương trình chạy bytecode: nạp class, verify, thông dịch + JIT, quản lý bộ nhớ.1
JRE / JDKJRE = JVM + thư viện chuẩn. JDK = JRE + công cụ phát triển (javac, javap, jcmd...).1
class loaderThành phần tìm và nạp class vào JVM, lười (chỉ khi cần dùng).1
verifierKiểm tra bytecode hợp lệ, an toàn trước khi chạy.1
interpreterChạy bytecode từng lệnh một. Khởi động nhanh, chạy chậm.1
JITJust-In-Time compiler: dịch đoạn code "nóng" sang mã máy lúc đang chạy.1
mixed modeChế độ mặc định của HotSpot: thông dịch + JIT.1
operand stackNgăn xếp tạm trong mỗi frame. Lệnh bytecode lấy giá trị từ đây và đẩy kết quả lên đây.1
local variable slotÔ biến cục bộ đánh số trong frame. Slot 0 = this (method thường) hoặc tham số đầu (method static).1
CDSClass Data Sharing: bản chụp sẵn các class lõi để JVM khởi động nhanh ("shared objects file").1
invokedynamicLệnh gọi mà đích được quyết định lúc chạy. Dùng cho nối chuỗi (Java 9+), lambda.1
stack (thread stack)Vùng nhớ riêng của mỗi thread, chứa các frame. Kích thước cố định (mặc định 1 MB, -Xss). Đầy → StackOverflowError.2
frameSinh ra mỗi lần gọi method: local variable slots + operand stack. Bị bỏ khi method return. Kích thước do javac tính sẵn (stack=, locals=).2
heapVùng nhớ dùng chung giữa các thread, chứa mọi object và mảng (new). GC dọn object không còn được tham chiếu. Đầy → OutOfMemoryError.2
reference (tham chiếu)Giá trị trỏ tới một object trên heap. Slot và field chỉ chứa primitive hoặc reference, không bao giờ chứa nguyên object.2
pass-by-valueCách Java luôn truyền tham số: sao chép giá trị (primitive hoặc reference) sang frame mới. Method sửa được object, nhưng không đổi được biến của caller.2
==So sánh hai giá trị trong slot. Với object, đó là so tham chiếu ("cùng một object?"). Bytecode: if_acmpne (ref), if_icmpne (int).3
equalsMethod so sánh logic do class định nghĩa. Mặc định trong Object là this == obj.3
hashCode contracta.equals(b) ⇒ a.hashCode() == b.hashCode() (bắt buộc). Chiều ngược lại không cần. Override equals thì phải override hashCode.3
identity hashGiá trị Object.hashCode() mặc định, gắn với từng object, không phụ thuộc field.3
bucketMột ô trong mảng table của HashMap. Chọn bằng (n-1) & hash. Lookup: bucket → so hash → ==/equals.3
collisionHai key khác nhau cùng rơi vào một bucket. Hợp lệ, nhưng quá nhiều sẽ làm lookup chậm.3
recordClass dữ liệu (Java 16+). Compiler tự sinh equals/hashCode/toString theo mọi component.3
string literalChuỗi viết thẳng trong code bằng dấu nháy kép, ví dụ "hi". Luôn được lấy từ String pool.4
String pool"Kệ chung" chứa các string literal. Literal giống nhau dùng chung một object. Nằm trong heap (từ Java 7).4
intern()Trả về bản String trên kệ có cùng nội dung (chưa có thì đặt lên kệ).4
immutable (bất biến)Tạo xong thì không sửa được. String là immutable: toUpperCase(), trim()... đều trả về String mới.4
Integer cache"Kệ chung" cho Integer từ -128 đến 127. Ngoài khoảng này, mỗi lần là object mới, nên == ra false.4
khởi tạo class (class initialization)Chạy khối static và gán giá trị biến static. Xảy ra một lần, vào lần đầu class được dùng (new, gọi method static, đọc/gán biến static không phải hằng số, class con được khởi tạo).5
<clinit>Method ẩn do javac tạo ra, gom mọi khối static và lệnh gán static. javap hiện thành static {};.5
compile-time constantstatic final với giá trị viết sẵn (số, chuỗi). javac chép thẳng giá trị vào chỗ dùng, nên đọc nó không kích hoạt khởi tạo class.5
ExceptionInInitializerErrorLỗi ném ra ở lần đầu khi khối static bị lỗi. Lỗi gốc nằm trong getCause().5
NoClassDefFoundError: Could not initialize class XLỗi ở các lần sau: class X đã bị đánh dấu hỏng. File không hề thiếu. Hãy tìm ExceptionInInitializerError đầu tiên trong log.5
warm-up (khởi động máy)Giai đoạn đầu sau khi JVM khởi động: code còn chạy thông dịch nên chậm, rồi nhanh dần khi JIT biên dịch code "nóng". Gây latency cao ngay sau deploy.6
tiered compilationBiên dịch phân tầng (mặc định): thông dịch → C1 (biên dịch nhanh, tầng 3) → C2 (tối ưu mạnh, tầng 4).6
C1 / C2Hai trình JIT của HotSpot. C1 dịch nhanh, tối ưu vừa phải. C2 dịch lâu hơn nhưng cho mã máy nhanh nhất.6
OSR (On-Stack Replacement)JIT biên dịch và thay code ngay giữa một vòng lặp đang chạy. Hiện bằng dấu % trong -XX:+PrintCompilation.6
JMHCông cụ đo hiệu năng chính thức của OpenJDK. Tự lo warm-up và chống JIT bỏ qua phép tính.6
GC (Garbage Collector)Trình dọn rác của JVM: tự giải phóng object không còn đi tới được. Mặc định Java 21 là G1.7
GC rootĐiểm xuất phát khi GC lần dấu: biến trong các method đang chạy, biến static... Object không đi tới được từ root nào = rác.7
memory leak (Java)Vô tình vẫn giữ tham chiếu tới object không dùng nữa (hay gặp: List/Map static chỉ thêm không xoá). GC không dọn được → OutOfMemoryError.7
OutOfMemoryError: Java heap spaceHeap đầy, GC dọn xong vẫn không đủ chỗ cho object mới.7
heap dump (.hprof)Ảnh chụp toàn bộ heap. Phân tích bằng Eclipse MAT / VisualVM để biết ai đang giữ object.7
Young / Old generationKhu chứa object mới (dọn thường xuyên, nhanh) và khu chứa object sống lâu. Pause Full = dọn toàn bộ heap, chậm nhất.7
Big-OCách mô tả thời gian chạy tăng thế nào khi dữ liệu lớn lên. O(1): không phụ thuộc số phần tử. O(n): tỷ lệ với số phần tử.8
capacity (dung lượng)Độ dài mảng bên trong ArrayList (≥ size). Mặc định 10 ở lần add đầu; đầy thì giãn ~1,5 lần (10 → 15 → 22 → 33...).8
amortized O(1)"Nhanh tính trung bình": thỉnh thoảng một lần tốn công (giãn mảng), nhưng chia đều cho mọi lần thì vẫn là O(1). Ví dụ: ArrayList.add.8
ArrayDequeHàng đợi/stack dựa trên mảng vòng. Thêm/lấy ở cả hai đầu đều O(1). Dùng thay LinkedList và thay ArrayList.remove(0).8
load factorTỷ lệ đầy cho phép trước khi HashMap giãn. Mặc định 0.75: 16 ngăn chứa tối đa 12 phần tử, phần tử thứ 13 làm map nhân đôi lên 32 ngăn.9
resize (HashMap)Nhân đôi số ngăn và tính lại ngăn cho từng phần tử. Tránh bằng HashMap.newHashMap(n) khi biết trước số phần tử.9
chọn ngăn(n - 1) & (h ^ (h >>> 16)), với h = hashCode(). Với Integer nhỏ và 16 ngăn: ngăn = số % 16.9
treeifyNgăn có ≥ 8 phần tử (và map ≥ 64 ngăn) thì chuỗi đổi thành cây đỏ đen, tìm trong ngăn còn O(log n). Từ Java 8.9
LinkedHashMap / TreeMapLinkedHashMap giữ thứ tự thêm vào; TreeMap sắp theo key. HashMap không đảm bảo thứ tự, và thứ tự có thể đổi sau resize.9
thread (luồng)Một dòng chạy code. Nhiều thread chạy song song, dùng chung heap (và biến static). Spring/Tomcat: mỗi request một thread.10
race conditionNhiều thread cùng đọc–sửa–ghi dữ liệu dùng chung; kết quả phụ thuộc thứ tự chen ngang → mất dữ liệu, không báo lỗi.10
atomic (nguyên tử)Thao tác không thể bị chia cắt / chen ngang. count++ không atomic (getstatic → iadd → putstatic).10
synchronizedKhoá: mỗi lúc chỉ một thread được vào khối/method; đồng thời đảm bảo thread sau nhìn thấy thay đổi của thread trước.10
AtomicInteger / AtomicLongBiến số với thao tác atomic (incrementAndGet...). Lựa chọn tốt nhất cho biến đếm dùng chung.10
ConcurrentHashMapMap thread-safe, dùng thay HashMap khi nhiều thread cùng đọc/ghi.10
thread-safeDùng đúng khi nhiều thread truy cập cùng lúc mà không cần khoá thêm. HashMap, ArrayList không thread-safe.10
deadlock (khoá chết)Các thread chờ nhau vòng tròn: mỗi thread giữ một khoá và chờ khoá thread khác đang giữ. Chương trình đứng im, không lỗi, CPU thấp.11
thread dumpẢnh chụp tức thời mọi thread: tên, trạng thái, dòng code đang chạy, khoá đang giữ (locked) và đang chờ (waiting to lock).11
PIDMã số tiến trình do hệ điều hành cấp. Lấy bằng jps.11
Thread stateRUNNABLE (đang chạy) · BLOCKED (chờ vào synchronized) · WAITING (chờ không hạn) · TIMED_WAITING (chờ có hạn, vd. sleep).11
lock orderingQuy tắc chống deadlock: mọi thread lấy các khoá theo cùng một thứ tự.11
reflectionCode đọc/dùng thông tin về class, method, field, annotation lúc chạy: getMethod, isAnnotationPresent, invoke. Nền móng của Spring.12
annotationNhãn dán (metadata) lên class/method/field. Tự nó không làm gì; phải có code khác đọc nó. Muốn đọc lúc chạy thì cần @Retention(RUNTIME) (mặc định là CLASS).12
proxyObject "đứng giữa", cùng interface với object thật; mọi lời gọi đi qua nó trước để làm thêm việc (transaction, log...) rồi mới tới object thật.12
dynamic proxyProxy có class được JVM sinh ra lúc chạy: Proxy.newProxyInstance + InvocationHandler (cần interface). Spring còn dùng CGLIB (class con).12
self-invocationMethod gọi method khác trong cùng object qua this → không đi qua proxy → @Transactional/@Async/@Cacheable bị bỏ qua.12
visibility (nhìn thấy)Thread này ghi, thread kia có thấy giá trị mới không. Không có happens-before thì không đảm bảo (JIT/cache CPU có thể giữ giá trị cũ mãi).13
volatileGhi vào biến volatile happens-before mọi lần đọc sau → luôn thấy giá trị mới. Không làm count++ thành atomic.13
Java Memory Model (JMM)Bộ luật (JLS ch.17) quy định thread nào nhìn thấy giá trị nào, khi nào.13
happens-beforeNếu X happens-before Y thì mọi thứ ghi trước X đều thấy được ở Y. Nguồn: ghi/đọc volatile; unlock/lock cùng monitor; start(); join().13
AtomicBooleanCờ boolean với get/set có hiệu ứng như volatile, cộng thêm thao tác atomic (compareAndSet).13
thread poolNhóm thread tạo sẵn, dùng lại cho nhiều việc; việc mới chờ trong hàng đợi. Nhanh hơn nhiều so với new Thread cho mỗi việc. Tomcat = thread pool (mặc định 200).14
ExecutorServiceGiao việc cho pool: submit(...). Dùng xong phải shutdown() (hoặc try (...), Java 19+), nếu không thread pool giữ JVM sống mãi.14
Future"Phiếu hẹn" kết quả của việc đã submit. get() chờ tới khi có kết quả.14
virtual threadThread nhẹ do JVM quản lý (Java 21, JEP 444). Rẻ, tạo hàng triệu cái được; hợp với việc chủ yếu chờ I/O, không giúp việc tính toán nặng.14
final (biến/field)Không được gán lại. Với object: chỉ tham chiếu cố định, object vẫn sửa được (final List vẫn add được). final ≠ immutable.15
final (method / class)Method: cấm override. Class: cấm kế thừa (vd. String). Proxy CGLIB không chặn được method/class final → @Transactional mất tác dụng.15
effectively finalBiến cục bộ không có chữ final nhưng không bao giờ bị gán lại. Lambda chỉ được dùng biến final hoặc effectively final.15
defensive copyChép ra bản riêng (vd. List.copyOf) khi nhận/trả object sửa được, để bên ngoài không sửa được trạng thái bên trong.15

Class bất biến (immutable)

record DonHang(List<String> monHang) {
    DonHang { monHang = List.copyOf(monHang); }   // defensive copy, bản không sửa được
}
  • Field private final, không setter; chép phòng thủ field sửa được; class final hoặc record.
  • Field final được JMM đảm bảo hiển thị đúng cho thread khác sau khi constructor chạy xong (JLS §17.5) → immutable object an toàn để chia sẻ.

Thread pool

try (ExecutorService pool = Executors.newFixedThreadPool(8)) {   // tự shutdown khi hết khối
    Future<Long> f = pool.submit(() -> tinh());
    long kq = f.get();                                             // chờ kết quả
}
Executors.newVirtualThreadPerTaskExecutor()                       // Java 21, cho việc chờ I/O
  • Chương trình không thoát + thread dump có pool-N-thread-M WAITING ở LinkedBlockingQueue.take → quên shutdown().
  • newFixedThreadPool dùng hàng đợi không giới hạn → việc dồn nhanh hơn tốc độ xử lý có thể gây OOM.

  • Treo + thread BLOCKED + CPU ~0% → deadlock (bài 11).
  • Treo + thread RUNNABLE + CPU 100% → vòng lặp không thoát (vd. cờ thiếu volatile).

Vì sao @Transactional "không chạy"?

  • Gọi nội bộ qua this (self-invocation) → tách sang bean khác.
  • Method private / final / static → proxy không chặn được.
  • Object không phải bean Spring (tự new) → không có proxy.

Ứng dụng treo: chụp và đọc thread dump

jps                          # tìm PID của chương trình Java
jcmd <PID> Thread.print      # chụp thread dump (khuyến nghị)
jstack <PID>                 # lệnh cũ, kết quả tương tự
  • Chụp 2–3 lần cách nhau vài giây, trước khi restart.
  • Tìm Found one Java-level deadlock; hoặc thread đứng yên ở cùng dòng code qua các lần chụp; hoặc nhiều thread BLOCKED cùng chờ một khoá.
  • Đặt tên cho thread (new Thread(task, "ten-ro-rang")) để dump dễ đọc.

Đo hiệu năng đúng cách

  • Không đo bằng một lần chạy: lần đầu là đo tốc độ thông dịch, sai lệch hơn 10 lần.
  • Khởi động trước (gọi nhiều lần không đo), rồi đo nhiều lần lấy trung bình; luôn dùng kết quả tính được.
  • Đo nghiêm túc → dùng JMH.
java -Xint X                                   # chỉ thông dịch (thí nghiệm, không dùng production)
java -XX:+PrintCompilation X | grep 'X::tenHam' # xem hàm nào được JIT, ở tầng nào

Thứ tự khởi tạo (cha – con)

new Child() lần đầu:  static cha → static con → constructor cha → constructor con
new Child() lần sau:                            constructor cha → constructor con

Quy tắc so sánh

  • So sánh nội dung của object (String, Integer, Long...) → luôn dùng .equals().
  • == chỉ dùng cho số nguyên thuỷ (int, long...) hoặc khi thật sự muốn hỏi "có cùng một object không".
  • Dữ liệu từ bên ngoài (người dùng, HTTP, database, file) không nằm trong String pool → == sẽ sai.

Checklist equals/hashCode

  • Override equals → override hashCode trên đúng các field đó (Objects.hash(...)), hoặc dùng record.
  • Không sửa field tham gia vào hashCode khi object đang nằm trong HashSet/HashMap.
  • Hash phải phân tán đều: đúng contract nhưng trùng hết (ví dụ luôn trả 42) sẽ làm lookup chậm hàng trăm lần.
