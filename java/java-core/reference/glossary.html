Glossary

Thuật ngữ Java core dùng thống nhất trong mọi bài. Thêm dần theo từng bài.

Thứ tự học và những gì còn phải học: Lộ trình.

Thuật ngữNghĩaBài
bytecodeTập lệnh cho JVM (máy ảo), không phụ thuộc OS/CPU. Nằm trong file .class.1
class fileFile .class: magic CAFEBABE + version + constant pool + field/method + bytecode. Mỗi class là một file.1
major versionPhiên bản class file. 52 = Java 8, 61 = Java 17, 65 = Java 21. Nếu JVM cũ hơn → UnsupportedClassVersionError.1
javacCompiler: .java → .class. Chạy lúc build.1
JVMChương trình chạy bytecode: nạp class, verify, thông dịch + JIT, quản lý bộ nhớ.1
JRE / JDKJRE = JVM + thư viện chuẩn. JDK = JRE + công cụ phát triển (javac, javap, jcmd...).1
class loaderThành phần tìm và nạp class vào JVM, lười (chỉ khi cần dùng).1
verifierKiểm tra bytecode hợp lệ, an toàn trước khi chạy.1
interpreterChạy bytecode từng lệnh một. Khởi động nhanh, chạy chậm.1
JITJust-In-Time compiler: dịch đoạn code "nóng" sang mã máy lúc đang chạy.1
mixed modeChế độ mặc định của HotSpot: thông dịch + JIT.1
operand stackNgăn xếp tạm trong mỗi frame. Lệnh bytecode lấy giá trị từ đây và đẩy kết quả lên đây.1
local variable slotÔ biến cục bộ đánh số trong frame. Slot 0 = this (method thường) hoặc tham số đầu (method static).1
CDSClass Data Sharing: bản chụp sẵn các class lõi để JVM khởi động nhanh ("shared objects file").1
invokedynamicLệnh gọi mà đích được quyết định lúc chạy. Dùng cho nối chuỗi (Java 9+), lambda.1
stack (thread stack)Vùng nhớ riêng của mỗi thread, chứa các frame. Kích thước cố định (mặc định 1 MB, -Xss). Đầy → StackOverflowError.2
frameSinh ra mỗi lần gọi method: local variable slots + operand stack. Bị bỏ khi method return. Kích thước do javac tính sẵn (stack=, locals=).2
heapVùng nhớ dùng chung giữa các thread, chứa mọi object và mảng (new). GC dọn object không còn được tham chiếu. Đầy → OutOfMemoryError.2
MetaspaceVùng native memory (ngoài heap) chứa thông tin class: tên, field, method, bytecode. Thay PermGen từ Java 8. Mặc định không giới hạn; đặt -XX:MaxMetaspaceSize. Đầy → OutOfMemoryError: Metaspace (quá nhiều class: proxy, CGLIB, ClassLoader bị giữ).2
reference (tham chiếu)Giá trị trỏ tới một object trên heap. Slot và field chỉ chứa primitive hoặc reference, không bao giờ chứa nguyên object.2
pass-by-valueCách Java luôn truyền tham số: sao chép giá trị (primitive hoặc reference) sang frame mới. Method sửa được object, nhưng không đổi được biến của caller.2
==So sánh hai giá trị trong slot. Với object, đó là so tham chiếu ("cùng một object?"). Bytecode: if_acmpne (ref), if_icmpne (int).3
equalsMethod so sánh logic do class định nghĩa. Mặc định trong Object là this == obj.3
hashCode contracta.equals(b) ⇒ a.hashCode() == b.hashCode() (bắt buộc). Chiều ngược lại không cần. Override equals thì phải override hashCode.3
identity hashGiá trị Object.hashCode() mặc định, gắn với từng object, không phụ thuộc field.3
bucketMột ô trong mảng table của HashMap. Chọn bằng (n-1) & hash. Lookup: bucket → so hash → ==/equals.3
collisionHai key khác nhau cùng rơi vào một bucket. Hợp lệ, nhưng quá nhiều sẽ làm lookup chậm.3
recordClass dữ liệu (Java 16+). Compiler tự sinh equals/hashCode/toString theo mọi component.3
string literalChuỗi viết thẳng trong code bằng dấu nháy kép, ví dụ "hi". Luôn được lấy từ String pool.4
String pool"Kệ chung" chứa các string literal. Literal giống nhau dùng chung một object. Nằm trong heap (từ Java 7).4
intern()Trả về bản String trên kệ có cùng nội dung (chưa có thì đặt lên kệ).4
immutable (bất biến)Tạo xong thì không sửa được. String là immutable: toUpperCase(), trim()... đều trả về String mới.4
Integer cache"Kệ chung" cho Integer từ -128 đến 127. Ngoài khoảng này, mỗi lần là object mới, nên == ra false.4
StringBuilder"Bảng trắng" sửa được: append viết vào cùng object (mảng tự nới, 16 → 34 → 70…). Dùng khi ghép chuỗi trong vòng lặp; s += x trong vòng lặp chậm theo bình phương. Không an toàn khi nhiều thread cùng viết.4
StringBufferGiống StringBuilder nhưng mọi method synchronized: an toàn đa luồng, chậm hơn. Có từ Java 1.0; code mới hầu như luôn dùng StringBuilder.4
khởi tạo class (class initialization)Chạy khối static và gán giá trị biến static. Xảy ra một lần, vào lần đầu class được dùng (new, gọi method static, đọc/gán biến static không phải hằng số, class con được khởi tạo).5
<clinit>Method ẩn do javac tạo ra, gom mọi khối static và lệnh gán static. javap hiện thành static {};.5
compile-time constantstatic final với giá trị viết sẵn (số, chuỗi). javac chép thẳng giá trị vào chỗ dùng, nên đọc nó không kích hoạt khởi tạo class.5
ExceptionInInitializerErrorLỗi ném ra ở lần đầu khi khối static bị lỗi. Lỗi gốc nằm trong getCause().5
NoClassDefFoundError: Could not initialize class XLỗi ở các lần sau: class X đã bị đánh dấu hỏng. File không hề thiếu. Hãy tìm ExceptionInInitializerError đầu tiên trong log.5
warm-up (khởi động máy)Giai đoạn đầu sau khi JVM khởi động: code còn chạy thông dịch nên chậm, rồi nhanh dần khi JIT biên dịch code "nóng". Gây latency cao ngay sau deploy.8
tiered compilationBiên dịch phân tầng (mặc định): thông dịch → C1 (biên dịch nhanh, tầng 3) → C2 (tối ưu mạnh, tầng 4).8
C1 / C2Hai trình JIT của HotSpot. C1 dịch nhanh, tối ưu vừa phải. C2 dịch lâu hơn nhưng cho mã máy nhanh nhất.8
OSR (On-Stack Replacement)JIT biên dịch và thay code ngay giữa một vòng lặp đang chạy. Hiện bằng dấu % trong -XX:+PrintCompilation.8
JMHCông cụ đo hiệu năng chính thức của OpenJDK. Tự lo warm-up và chống JIT bỏ qua phép tính.8
GC (Garbage Collector)Trình dọn rác của JVM: tự giải phóng object không còn đi tới được. Mặc định Java 21 là G1.9
GC rootĐiểm xuất phát khi GC lần dấu: biến trong các method đang chạy, biến static... Object không đi tới được từ root nào = rác.9
memory leak (Java)Vô tình vẫn giữ tham chiếu tới object không dùng nữa (hay gặp: List/Map static chỉ thêm không xoá). GC không dọn được → OutOfMemoryError.9
OutOfMemoryError: Java heap spaceHeap đầy, GC dọn xong vẫn không đủ chỗ cho object mới.9
heap dump (.hprof)Ảnh chụp toàn bộ heap. Phân tích bằng Eclipse MAT / VisualVM để biết ai đang giữ object.9
Young / Old generationKhu chứa object mới (dọn thường xuyên, nhanh) và khu chứa object sống lâu. Pause Full = dọn toàn bộ heap, chậm nhất.9
Big-OCách mô tả thời gian chạy tăng thế nào khi dữ liệu lớn lên. O(1): không phụ thuộc số phần tử. O(n): tỷ lệ với số phần tử.10
capacity (dung lượng)Độ dài mảng bên trong ArrayList (≥ size). Mặc định 10 ở lần add đầu; đầy thì giãn ~1,5 lần (10 → 15 → 22 → 33...).10
amortized O(1)"Nhanh tính trung bình": thỉnh thoảng một lần tốn công (giãn mảng), nhưng chia đều cho mọi lần thì vẫn là O(1). Ví dụ: ArrayList.add.10
ArrayDequeHàng đợi/stack dựa trên mảng vòng. Thêm/lấy ở cả hai đầu đều O(1). Dùng thay LinkedList và thay ArrayList.remove(0).10
load factorTỷ lệ đầy cho phép trước khi HashMap giãn. Mặc định 0.75: 16 ngăn chứa tối đa 12 phần tử, phần tử thứ 13 làm map nhân đôi lên 32 ngăn.11
resize (HashMap)Nhân đôi số ngăn và tính lại ngăn cho từng phần tử. Tránh bằng HashMap.newHashMap(n) khi biết trước số phần tử.11
chọn ngăn(n - 1) & (h ^ (h >>> 16)), với h = hashCode(). Với Integer nhỏ và 16 ngăn: ngăn = số % 16.11
treeifyNgăn có ≥ 8 phần tử (và map ≥ 64 ngăn) thì chuỗi đổi thành cây đỏ đen, tìm trong ngăn còn O(log n). Từ Java 8.11
LinkedHashMap / TreeMapLinkedHashMap giữ thứ tự thêm vào; TreeMap sắp theo key. HashMap không đảm bảo thứ tự, và thứ tự có thể đổi sau resize.11
thread (luồng)Một dòng chạy code. Nhiều thread chạy song song, dùng chung heap (và biến static). Spring/Tomcat: mỗi request một thread.12
race conditionNhiều thread cùng đọc–sửa–ghi dữ liệu dùng chung; kết quả phụ thuộc thứ tự chen ngang → mất dữ liệu, không báo lỗi.12
atomic (nguyên tử)Thao tác không thể bị chia cắt / chen ngang. count++ không atomic (getstatic → iadd → putstatic).12
synchronizedKhoá: mỗi lúc chỉ một thread được vào khối/method; đồng thời đảm bảo thread sau nhìn thấy thay đổi của thread trước.12
AtomicInteger / AtomicLongBiến số với thao tác atomic (incrementAndGet...). Lựa chọn tốt nhất cho biến đếm dùng chung.12
ConcurrentHashMapMap thread-safe, dùng thay HashMap khi nhiều thread cùng đọc/ghi.12
thread-safeDùng đúng khi nhiều thread truy cập cùng lúc mà không cần khoá thêm. HashMap, ArrayList không thread-safe.12
deadlock (khoá chết)Các thread chờ nhau vòng tròn: mỗi thread giữ một khoá và chờ khoá thread khác đang giữ. Chương trình đứng im, không lỗi, CPU thấp.13
thread dumpẢnh chụp tức thời mọi thread: tên, trạng thái, dòng code đang chạy, khoá đang giữ (locked) và đang chờ (waiting to lock).13
PIDMã số tiến trình do hệ điều hành cấp. Lấy bằng jps.13
Thread stateRUNNABLE (đang chạy) · BLOCKED (chờ vào synchronized) · WAITING (chờ không hạn) · TIMED_WAITING (chờ có hạn, vd. sleep).13
lock orderingQuy tắc chống deadlock: mọi thread lấy các khoá theo cùng một thứ tự.13
reflectionCode đọc/dùng thông tin về class, method, field, annotation lúc chạy: getMethod, isAnnotationPresent, invoke. Nền móng của Spring.14
annotationNhãn dán (metadata) lên class/method/field. Tự nó không làm gì; phải có code khác đọc nó. Muốn đọc lúc chạy thì cần @Retention(RUNTIME) (mặc định là CLASS).14
proxyObject "đứng giữa", cùng interface với object thật; mọi lời gọi đi qua nó trước để làm thêm việc (transaction, log...) rồi mới tới object thật.14
dynamic proxyProxy có class được JVM sinh ra lúc chạy: Proxy.newProxyInstance + InvocationHandler (cần interface). Spring còn dùng CGLIB (class con).14
self-invocationMethod gọi method khác trong cùng object qua this → không đi qua proxy → @Transactional/@Async/@Cacheable bị bỏ qua.14
visibility (nhìn thấy)Thread này ghi, thread kia có thấy giá trị mới không. Không có happens-before thì không đảm bảo (JIT/cache CPU có thể giữ giá trị cũ mãi).15
volatileGhi vào biến volatile happens-before mọi lần đọc sau → luôn thấy giá trị mới. Không làm count++ thành atomic.15
Java Memory Model (JMM)Bộ luật (JLS ch.17) quy định thread nào nhìn thấy giá trị nào, khi nào.15
happens-beforeNếu X happens-before Y thì mọi thứ ghi trước X đều thấy được ở Y. Nguồn: ghi/đọc volatile; unlock/lock cùng monitor; start(); join().15
AtomicBooleanCờ boolean với get/set có hiệu ứng như volatile, cộng thêm thao tác atomic (compareAndSet).15
thread poolNhóm thread tạo sẵn, dùng lại cho nhiều việc; việc mới chờ trong hàng đợi. Nhanh hơn nhiều so với new Thread cho mỗi việc. Tomcat = thread pool (mặc định 200).16
ExecutorServiceGiao việc cho pool: submit(...). Dùng xong phải shutdown() (hoặc try (...), Java 19+), nếu không thread pool giữ JVM sống mãi.16
Future"Phiếu hẹn" kết quả của việc đã submit. get() chờ tới khi có kết quả.16
virtual threadThread nhẹ do JVM quản lý (Java 21, JEP 444). Rẻ, tạo hàng triệu cái được; hợp với việc chủ yếu chờ I/O, không giúp việc tính toán nặng.16
final (biến/field)Không được gán lại. Với object: chỉ tham chiếu cố định, object vẫn sửa được (final List vẫn add được). final ≠ immutable.17
final (method / class)Method: cấm override. Class: cấm kế thừa (vd. String). Proxy CGLIB không chặn được method/class final → @Transactional mất tác dụng.17
effectively finalBiến cục bộ không có chữ final nhưng không bao giờ bị gán lại. Lambda chỉ được dùng biến final hoặc effectively final.17
defensive copyChép ra bản riêng (vd. List.copyOf) khi nhận/trả object sửa được, để bên ngoài không sửa được trạng thái bên trong.17
thisTham chiếu tới object đang chạy method. JVM truyền ngầm vào slot 0 của mọi method không static và constructor (args_size = số tham số + 1). Không dùng được trong static.6
shadowing (che tên)Tham số/biến cục bộ trùng tên field sẽ che field. ten = ten chỉ gán tham số cho chính nó; phải viết this.ten = ten.6
this(...) / super(...)Gọi constructor khác cùng class / constructor của class cha. Phải là câu lệnh đầu tiên (Java 21; Java 25 nới lỏng, JEP 513).6
super.method()Gọi bản method của class cha, bỏ qua bản override. Dùng để mở rộng thay vì thay thế.6
overloading (nạp chồng)Nhiều method cùng tên, khác danh sách tham số, trong cùng class. Compiler chọn bản nào lúc biên dịch, dựa vào kiểu khai báo của đối số. Chỉ khác kiểu trả về → lỗi biên dịch.7
overriding (ghi đè)Class con viết lại method của cha với cùng chữ ký. JVM chọn bản nào lúc chạy, dựa vào object thật (invokevirtual). Gắn @Override để compiler bắt lỗi gõ sai.7
chữ ký method (signature)Tên method + danh sách kiểu tham số. Không gồm kiểu trả về, tên tham số, throws.7
dynamic dispatchCơ chế chọn bản override theo object thật lúc chạy. Là nền của đa hình (polymorphism) và của proxy CGLIB trong Spring.7
method hidingMethod static ở con trùng chữ ký với cha: không phải override, mà che. Bản được gọi phụ thuộc kiểu khai báo.7
abstract classClass chưa hoàn chỉnh: có field, constructor, method làm sẵn, và method abstract (không thân) để con làm. Không new được. Chỉ extends được một class.18
interfaceLời hứa "làm được việc gì". Method tự động public; field tự động public static final (không có trạng thái của object). Một class implements được nhiều interface.18
default methodMethod có thân trong interface (Java 8+), để thêm method mới mà không làm hỏng class cũ. Trùng default từ hai interface → phải override, gọi A.super.m().18
access modifierpublic > protected (cùng package + class con) > package-private (không ghi gì, cùng package) > private (cùng class). private theo class, không theo object.18
generics"Dán nhãn" kiểu cho class/method (List<String>) để compiler bắt lỗi kiểu lúc biên dịch thay vì ClassCastException lúc chạy.19
raw typeDùng class generic không có <...> (List trơn). Chỉ để tương thích code cũ; gây cảnh báo "unchecked". Không dùng trong code mới.19
type erasureCompiler kiểm tra <T> rồi xoá nó: lúc chạy List<String> và List<Integer> cùng là ArrayList; compiler tự chèn checkcast chỗ lấy ra. Vì vậy không có new T(), instanceof T.19
heap pollutionBiến kiểu List<String> trỏ tới list chứa thứ không phải String (lọt qua raw type/reflection). Nổ ClassCastException ở chỗ lấy ra, xa chỗ gây lỗi.19
invariant (bất biến)List<Integer> không phải List<Number>. Mảng thì covariant (Number[] = Integer[] được) nên phải kiểm tra lúc chạy: ArrayStoreException.19
wildcard / PECS? extends T: chỉ đọc ra (producer). ? super T: chỉ ghi vào (consumer). Vừa đọc vừa ghi: List<T>. "Producer Extends, Consumer Super".19
lambdaCài đặt ngắn cho method duy nhất của một functional interface: (a, b) -> .... Thân thành method private static lambda$...; chỗ tạo là invokedynamic + LambdaMetafactory (class dựng lúc chạy, không có file .class).20
functional interfaceInterface có đúng một method abstract (Predicate, Function, Supplier, Consumer, Comparator, Runnable). @FunctionalInterface nhờ compiler kiểm tra.20
method referenceString::length, System.out::println: cách viết gọn lambda chỉ gọi một method có sẵn.20
lazy (stream)filter/map (trung gian) chỉ lắp dây chuyền; chỉ chạy khi có thao tác cuối (collect, findFirst, count, forEach). Từng phần tử đi hết dây chuyền; dừng sớm; stream dùng một lần.20
common poolForkJoinPool.commonPool: pool chung (số lõi − 1 thread) cho mọi parallel stream và CompletableFuture mặc định của cả JVM. Không dùng cho việc chờ I/O.20
static nested classClass khai báo static bên trong class khác: độc lập, không giữ object ngoài. Tạo bằng new Ngoai.Nested(). Mặc định nên dùng (Builder, HashMap.Node).21
inner classClass lồng không static (kể cả class ẩn danh): mỗi object gắn với một object ngoài qua field ẩn this$0; tạo bằng ngoai.new Inner(). Bị giữ lâu (list static, listener) thì kéo theo cả object ngoài → rò rỉ.21
this$0Field ẩn compiler thêm vào inner class, trỏ tới object ngoài (xem bằng javap -p). Từ JDK 18 bị bỏ nếu inner class không dùng object ngoài, nhưng constructor vẫn đòi object ngoài.21
checked exceptionCon của Exception nhưng không qua RuntimeException (IOException, SQLException). Compiler bắt phải catch hoặc throws. Spring mặc định không rollback với loại này.22
unchecked exceptionCon của RuntimeException (NPE, IllegalArgumentException). Không bắt buộc xử lý. Spring mặc định rollback. Error (OOM, StackOverflow) cũng không bắt buộc và thường không nên bắt.22
try-with-resourcestry (A a = ...; B b = ...) {...}: tự đóng mọi AutoCloseable theo thứ tự ngược; lỗi khi đóng thành suppressed, không che lỗi gốc. Không bao giờ return trong finally (nuốt exception).22
OmitStackTraceInFastThrowTối ưu JIT: chỗ ném NPE/ArithmeticException… liên tục được thay bằng exception tạo sẵn, không message, không stack trace. Tắt bằng -XX:-OmitStackTraceInFastThrow; hoặc tìm log những lần đầu.22
Comparable / ComparatorcompareTo trong class (thứ tự tự nhiên) / compare bên ngoài (nhiều cách xếp). Trả âm/0/dương. Dùng Integer.compare, Comparator.comparing(...).thenComparing(...); không trừ hai số (tràn).23

LinkedHashMapHashMap + chuỗi nối giữ thứ tự thêm vào; accessOrder = true + removeEldestEntry = LRU cache.23
ConcurrentModificationExceptionSửa collection trong lúc duyệt bằng iterator/for-each (thường chỉ 1 thread). Iterator so modCount với expectedModCount (fail-fast, không đảm bảo). Dùng removeIf / iterator.remove().23

this / super

this.ten = ten;            // field vs tham số trùng tên
this(ten, gia, 1);         // constructor gọi constructor (dòng đầu tiên)
super.moTa() + " VIP";     // gọi bản của cha rồi mở rộng
super("Bình");             // gọi constructor cha (dòng đầu tiên)
  • Không gọi method override được trong constructor: constructor cha chạy trước khi field của con được gán → bản override của con thấy null/0 (kể cả field final).
  • Không để lộ this ra ngoài khi constructor chưa xong (listener, list static, thread).

Quy tắc so sánh

  • So sánh nội dung của object (String, Integer, Long...) → luôn dùng .equals().
  • == chỉ dùng cho số nguyên thuỷ (int, long...) hoặc khi thật sự muốn hỏi "có cùng một object không".
  • Dữ liệu từ bên ngoài (người dùng, HTTP, database, file) không nằm trong String pool → == sẽ sai.

Checklist equals/hashCode

  • Override equals → override hashCode trên đúng các field đó (Objects.hash(...)), hoặc dùng record.
  • Không sửa field tham gia vào hashCode khi object đang nằm trong HashSet/HashMap.
  • Hash phải phân tán đều: đúng contract nhưng trùng hết (ví dụ luôn trả 42) sẽ làm lookup chậm hàng trăm lần.
