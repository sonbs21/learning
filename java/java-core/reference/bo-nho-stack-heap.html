Stack, Heap & pass-by-value

Một trang. In ra, dán cạnh màn hình.

Cái gì nằm ở đâu

ThứVị tríSống bao lâu
Biến local, tham số (mọi kiểu)Frame trên stack của threadTới khi method trả về
Object, mảng (new …)HeapTới khi không còn tham chiếu nào và GC thu hồi
Field của object (kể cả int)Bên trong object, tức trên heapCùng với object chứa nó

Biến primitive chứa giá trị. Biến reference chứa mũi tên (giá trị tham chiếu) hoặc null.

Quy tắc duy nhất khi gọi method

m(a) tạo frame mới, tạo biến tham số mới, rồi copy giá trị của a vào đó (JLS §8.4.1). Java luôn pass-by-value.

Câu trả lời phỏng vấn mẫu (30 giây)

“Java luôn pass-by-value. Với primitive, giá trị được copy là con số. Với object, giá trị được copy là reference, nên method sửa được trạng thái của object nhưng không gán lại được biến của người gọi. Ví dụ: hàm swap hai object không có tác dụng gì ở bên ngoài.”
